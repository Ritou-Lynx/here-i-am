# 记忆数据同步第一版验收

这份清单用于在不同电脑构建的 Here I am V3 之间验证聊天与 Memory V3 数据搬运，不依赖原开发会话。

## 当前边界

- 数据包扩展名：`.memexdata`。
- 云端对象：`here-i-am/data_latest.memexdata`，与配置包分开。
- 内容：聊天数据库、Memory V3 / Dreaming、工作区引用文件，以及完整备份中携带的可移植设置。
- 安全：同步口令通过 PBKDF2-SHA256（600,000 次）派生 AES-256-GCM 密钥；明文快照不上传。
- 完整性：先校验加密认证，再校验数据帧 SHA-256，最后校验 `.memex` manifest。
- 恢复保护：覆盖本机数据前，必须先创建 `memex_safety_before_memory_sync_import` 安全快照。
- 首版限制：单包不超过 128 MB；整包 last-writer-wins；没有后台自动同步，也不能合并两台设备同时新增的数据。

## 0. 安装前

1. 确认 `v3-lab`，记录 commit；只覆盖安装 `com.memexlab.hereiam.v3`，不要卸载。
2. 两台设备使用相同同步口令，并配置同一个 S3 bucket。
3. 至少准备一段可辨认的聊天、一张 Memory Card；如已有 Fragment / Episode，也记录数量。
4. 记录源端和目标端当前 chat / cards / fragments / episodes 数量。

## 1. 手动文件闭环

1. 源端进入“同步与迁移 → 聊天与记忆数据”，导出 `.memexdata`。
2. 把文件搬到目标端，选择“从数据快照恢复”。
3. 确认恢复警告明确说明会覆盖本机数据、不会自动合并。
4. 输入正确口令并恢复；完成后重启 App。
5. 检查聊天、Memory Card、Fragment / Episode、角色引用图片和相关设置是否与源端一致。
6. 检查备份页是否出现恢复前创建的 safety snapshot。

## 2. S3 往返

1. 私人电脑构建的 App 上传数据快照。
2. 工作电脑构建的 App 从云端恢复，重启后核对数据。
3. 只在工作电脑新增一段聊天或一张测试 Memory Card，再上传新快照。
4. 回到私人电脑，在没有新增本地数据的前提下从云端恢复并核对新增内容。
5. 整个往返期间不要让两端各自新增内容后再互相下载；第一版会以最后上传的整包覆盖。

## 3. 失败与安全检查

- 错误口令：必须在恢复前失败，本机数据不变，也不应创建无意义的 safety snapshot。
- 篡改密文：AES-GCM 校验失败，本机数据不变。
- 篡改解密后的数据帧或备份：SHA-256 / manifest 校验失败，本机数据不变。
- S3 没有数据对象：显示“云端没有加密包”，不得误下载配置对象。
- safety snapshot 创建失败：停止恢复，不能继续覆盖本机。
- 数据包超过 128 MB：明确提示首版容量限制，不尝试在手机内存中强行加密。

## 4. 本轮通过以后

1. 云端从单一 `latest` 对象升级为不可变版本对象 + `latest` 指针，保留可回滚历史。
2. 增加上传前后摘要和远端版本检查，防止旧设备静默覆盖更新数据。
3. 为聊天、Memory Card、Dreaming append-only 操作设计增量清单和幂等导入。
4. 明确冲突策略后再开放双端离线编辑与自动同步。
5. 最后才接 App 生命周期自动上传/拉取；未解决冲突前保持用户显式触发。
