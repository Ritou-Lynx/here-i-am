# Wave 1：桌面统一链接 / 视频导入

## 本轮闭环

- 桌面导入框接受纯 URL，也接受小红书、微信公众号等分享文案；从文本中提取一个或多个 HTTP(S) URL。
- 只有一个候选时直接预览；多个候选时由用户明确选择，避免静默导错。
- 网页与视频共用 `/import` 入口、同一套 `Source → SourceVersion → Card` 身份和“预览零写入、确认后提交”语义。
- YouTube 保留研读级路径；Bilibili 诚实保存为 `linkOnly` 视频来源，不伪装可控播放。

## 安全与数据边界

- 分享文本解析是纯本地字符串处理，不发请求、不写数据库。
- 真正抓取继续经过现有 DNS pin、SSRF、重定向、MIME 与 2 MiB 上限。
- 本轮不接入图片远程直载，不复制手机端未经桌面安全审计的下载器。

## 验证

- 完整小红书分享文案、Markdown 转义、多个 URL 与无 URL 的解析测试。
- Bilibili link-only 预览零抓取、零写入，确认后只创建一套身份。
- Widget 覆盖分享文案导入、多链接选择、Bilibili link-only 保存。

## 未完事项

- 小红书图片、图片 OCR、重要评论与普通网页原图需要先确定安全资产缓存 / `object_ref` / 评论证据契约，再进入下一波。
- Bilibili 与小红书没有稳定公开可控播放接口，当前不声明 seek、current time 或平台字幕能力。
