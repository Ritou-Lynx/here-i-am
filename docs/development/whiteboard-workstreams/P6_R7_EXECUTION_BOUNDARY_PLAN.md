## 生产接线的已核对缺口

当前 `CodexAppServerAdapter.startSession` 在 `_ensureReady` 前拒绝本 profile；HTTP API 只透传配置。不能先翻转 availability。普通适配器的 session close 只关闭本地 binding，没有每个 session 的子进程和代理所有权；其 reserved/startUnconfirmed 错误路径也不能代替 R7 的实际清理。

后续专用分支必须保留 `context_manifest.execution_epoch` 的真实租约值，持有同一 local session / provider thread / broker / native child，并在原生来源、网络及进程边界确证后才输出 v2 启动回执。对外 turn 使用 local ID，RPC/终态使用 provider ID；实际 stdin 派发回调记录 interrupt，匹配 `turn/completed` 记录 terminal。未知启动仍关闭 child/proxy，账本保留 unknown；只由最终账本产生专用 DELETE 回执。HTTP 断连与宿主退出不能丢失 owned-child 清理责任。现有普通会话行为保持独立，生产候选完成前不签隔离证明。

`CodexAppServerClient` 的现有注入点是同步 `spawnImpl`，不是异步 UAC 工厂。未来 IPC 包装需要先完成原生握手再提供 ChildProcess-like；helper 退出或 IPC 断连不得映射成 CLI 的 `close`。目前 `request()` 在 stdin.write 返回后调用 onDispatched；IPC 入队不满足这个含义。原生桥必须在实际写入受控 CLI stdin 后返回派发证据，并把该事实与 stdout notification 纳入同一宿主单调序列域。匹配终态必须在本次 interrupt 派发观察序号之后，ACK/响应/时间戳均不代替它。请求超时不证明未派发；原生清理所有权要独立保留。

## Windows 范围与实施顺序

威胁模型是受信宿主、固定 CLI 与操作系统，防止模型触发的工具调用绕过文字门。它不声称防御已被攻陷的同权账户、管理员或内核。配置回显、抓包观察或单个工具报错不能替代执行边界。

官方 Codex [网络代理范围](https://learn.chatgpt.com/docs/permissions#what-the-network-proxy-does-not-control) 不包括模型、认证等客户端服务流量，因此只设置命令 sandbox 的网络规则不足以隔离这里的模型通道。

Windows [回环配置接口](https://learn.microsoft.com/en-us/windows/win32/api/netfw/nf-netfw-networkisolationsetappcontainerconfig) 是整表 Get/Set，没有已验证的单 SID 原子增删或 CAS。helper 必须在无并行外部网络配置写者的维护窗口使用，写前重读和写后完整集合核验，只增删 own SID，不恢复旧全表快照。这能检测部分并发，不能保证不协作管理员同时修改时无丢失更新。

原生 helper 默认只读 plan/self-test。只有显式 synthetic 入口会创建一次性 profile、ACL 和网络规则；合成工作只使用本机监听器和无认证 worker，不读取登录目录、不连接真实 provider。只有进程关闭且 Job 归零证据成立才移除自己的网络边界；未知时保留拒绝并记录恢复事项。硬崩溃必须提供只针对 own attempt 的受限恢复入口。

顺序为：源码复核与只读编译验证 → 管理员权限下无认证合成验证 → 新 CLI 原生容器兼容与来源核验 → 真实专用账户单任务验证 → App 新候选与取消/执行/恢复验收。执行到需要 Windows 管理员窗口确认时，不能把用户此前登录当成操作系统提权。
