## 3. 已确认的产品裁决

### 3.1 富文本是块模型，但操作必须像连续文档

- 绿色矩形框不承担块级链接语义，也不是长期视觉规范，应删除常驻框。
- 内部可继续使用 `RichTextBlock`，但用户必须能跨块移动光标、连续退格合并、Delete 向下合并、Shift 选择、拖选和 Ctrl+A。
- 块类型控件明确提供 Paragraph / H1 / H2 / H3 / H4 / H5 / H6；将标题切回 Paragraph 是第一等操作。
- 块链接未来通过永久 block id、链接标记和反链面板表达，不能靠给每行画绿色框暗示。

### 3.2 白板内编辑是卡片表面原位编辑

- 双击空白创建真实 Note Card，并立即在画布卡片表面获得输入焦点。
- 双击普通 Note / Annotation Card 进入卡片内部紧凑编辑，不弹全局 Dialog。
- “新标签页全屏编辑”“ContextDock 侧面打开”“Pop 悬浮窗编辑”是额外打开方式，不替代原位编辑。
- Source Card 仍按媒介进入对应消费视图，不把网页 / 视频全文编辑塞进画布。

### 3.3 视觉连线与语义双链是两个层次

- `BoardEdge` 表达某张白板上两个 `BoardItem` 的视觉关系；端点必须由 `from_item_id / to_item_id + anchor side` 实时计算，不能保存成脱离卡片的静态屏幕坐标。
- 语义双链连接稳定 `card_id` 或永久 `block_id`，跨白板仍成立，并能形成反向引用列表。
- 把 Card A 与 Card B 画一条线，不自动等同于正文提及；若用户指定语义类型，可以在同一操作中显式创建语义关系。
- 当前项目只有 BoardEdge，不代表双链已经完成。Wave 3 必须先形成最小共享契约和可见入口，再实现 UI。

### 3.4 视频时间 Anchor 不依赖字幕

- 字幕是定位与阅读辅助，不是创建视频笔记的前置条件。
- 只要播放器能读取 current / duration 并 seek，用户就能在当前时间建立点 Anchor；可通过开始 / 结束操作建立区间 Anchor。
- 有字幕时 Anchor 可额外关联 cue id；无字幕时仍保存 `source_id + source_version_id + start_ms + end_ms`。
- 视频工具条或时间轴必须始终提供“在当前位置添加标注”，不能只把创建按钮放在字幕行旁。

### 3.5 统一导入，而不是让用户预判文件类型

- 产品只保留一个“导入卡片”入口，第一步选择“本地导入”或“链接导入”。
- 后台根据 MIME、扩展名、魔数、URL provider 与返回内容自动识别文本、Markdown、PDF、图片、音频、视频、网页等。
- 所有导入最终使用统一 `Source → SourceVersion → Card` 身份；类型只决定解析器与消费视图，不产生平行卡片库。
- 不确定或不支持时展示检测结果和原因，让用户修正；不要求用户退回去换图标重试。

### 3.6 删除与复用语义

- “从当前白板移除”只删除 BoardItem，不删除 Card / Source。
- “添加到其他白板”只新增 BoardItem，同一 Card 保持稳定身份。
- “复制卡片”默认生成新的 Card；“复制链接 / 引用”保持原 Card 身份。
- “彻底删除”必须明确影响全局 Card 及所有白板引用，并二次确认；默认优先软删除。

### 3.7 FlexNote 白板核心操作对齐规范（不可压缩为功能名）

这一节完整保存用户对 FlexNote 核心操作的参考描述。它是后续 W1 / W2 产品交互的行为规范，不能只在任务表中写成“补菜单”“补批量操作”后由实现者自行猜测。

#### 3.7.1 单张卡片：直接操作优先

**创建与输入**

- 双击白板空白处默认创建真实 Note Card；不弹窗，卡片直接进入表面编辑并获得输入焦点。
- 单击已有普通卡片可选择；双击进入卡片表面原位编辑。全局全屏编辑是用户主动选择的放大方式，不是双击默认结果。

**四向连线锚点**

- 选中或 hover 卡片时，四周显示上 / 右 / 下 / 左四个连线锚点。
- 从锚点直接拖出连线，落到另一卡片的锚点或边界完成连接；不经过“先多选 → 顶部连接 → 选择连线 → 输入标签”的反直觉流程。
- 端点绑定 BoardItem 与 anchor side；移动、缩放、撤销、重做、重启后始终跟随卡片。

**悬浮快捷按钮**

- 放大：在新标签 / 全屏工作面打开卡片。
- 切换颜色：展示少量常用预设，先改 Card presentation，不新造内容身份。
- 添加到白板：打开 BoardTargetPicker，列出最近白板、全部白板搜索与新建白板；确认后复用同一 Card，只新增目标 BoardItem。
- 更多：使用省略号图标；与右键菜单调用同一命令集合，不能形成两套行为。

#### 3.7.2 卡片右键 / 更多菜单：完整命令集合

1. **切换颜色**：与悬浮快捷按钮共享预设和当前状态。
2. **复制卡片**：复制完整 Card 内容形成新的 Card，可切换白板后粘贴；不得误实现为只复制当前 BoardItem 坐标。
3. **复制链接**：复制稳定卡片跳转链接。粘入其他卡片时形成可点击的引用文本，可跳转或预览，并进入语义双链 / 反链体系；不能复制成一段失去 card_id 的普通文字。
4. **打开方式**：
   - 在侧边辅助面打开：使用当前工作面的 ContextDock / 三栏对照布局，不恢复全局永久右侧栏；
   - 在 Pop 悬浮窗打开：非模态，可编辑，关闭后完整退场；
   - 在新标签 / 全屏工作面打开：用于完整编辑与专注查看。
5. **查看信息**：由叹号信息动作进入，展示创建时间、更新时间、标签、所属白板、历史版本；历史版本支持查看差异并显式恢复。
6. **导出**：导出 Markdown、复制为 Markdown、导出 PDF、导出 Word。每种格式必须产生真实可打开产物，不以按钮占位验收。
7. **管理标签**：增删 Card 的全局显式标签；与卡片库筛选使用同一词汇和 Repository。
8. **白板与删除语义**：
   - 添加到白板：复用同一 Card，新增 BoardItem；
   - 从当前白板移除：只删除当前 BoardItem；
   - 删除：全局软删除 Card，并明确所有白板引用受影响，危险确认后执行。

#### 3.7.3 多选卡片：选择后就地出现批量悬浮栏

框选、Shift/Ctrl 多选完成后，在选择区域附近出现悬浮操作栏；不要求用户移到窗口顶端寻找命令。

- **全局颜色替换**：分别支持统一修改卡片填充色、文字色、文字背景色；界面必须明确三个目标，不能只写一个含糊“颜色”。
- **聚焦视窗**：根据选中包围盒自适应缩放并居中，保留合理安全边距。
- **排列与对齐**：至少包含水平居中、垂直居中、顶部对齐、底部对齐；后续可增加左 / 右对齐、等距分布，但不能用“自动布局”替代明确命令。
- **创建分组**：立即生成半透明分组框并进入命名；分组的后续菜单包含更改框颜色、重命名、添加到其他白板、解除分组。
- **整体复用与移动**：批量复制到其他白板、批量添加到其他白板，两者分别对应“新 Card”与“同 Card 新 BoardItem”，不可混淆。
- **批量管理标签**：对选中 Card 统一增加或移除显式标签，保持幂等。

#### 3.7.4 全局常驻悬浮功能栏

这里的“常驻”是指在白板工作面内无需先选对象即可调用，并非恢复窗口顶栏；整组工具仍是悬浮面，可按沉浸规则收起并完整退场。

- **创建卡片**：点击卡片图标，在当前 viewport 合理位置生成真实 Card 并直接输入。
- **书写 / 涂鸦工具**：
  - 画笔：可调粗细与颜色；
  - 荧光笔：独立透明度与混合语义；
  - 橡皮擦：删除笔迹对象，不误删下方 Card / BoardEdge。

手绘不是“在 Canvas 上画完就算完成”：笔迹需要独立稳定身份、撤销重做、保存与重启恢复；在共享契约未裁决前，功能栏可以设计但不得用不可恢复的临时 painter 冒充交付。

#### 3.7.5 渐进披露与一致性

- 高频动作放悬浮快捷按钮；完整动作放右键 / 更多；对象未选中时不铺满按钮。
- 同一个命令在快捷按钮、右键菜单、键盘快捷键和批量栏中必须调用同一业务动作与权限 / 撤销链。
- 悬浮栏、菜单、ContextDock 和 Pop 关闭后完整退场，不增加常驻顶栏、固定右侧栏或遮挡画布的兜底矩形。
- 快捷操作不能绕过只读、授权、Repository、操作审计或撤销语义。

### E — W0 双链与块引用契约（先设计，后实现）

目标：LK-01。

这是共享契约工作，不与 A/B 同时静默改 schema。先给出 ADR 与最小 fixture，明确：

- `CardLink` / `BlockReference` 的稳定 ID、方向、关系类型、源 / 目标、软删除；
- RichText block 的永久 block id 与迁移；
- `@mention`、`[[keyword]]`、复制卡片链接的统一解析；
- 反向查询、悬浮预览、定位目标 Card / block；
- 与 BoardEdge 的可选关联，但不互相替代。

最小产品验收：在卡片 A 输入对卡片 B 的引用，B 的反链面板立即出现 A；点击可定位，重启后仍存在；引用块被编辑或删除后关系正确更新并可撤销。

### F — W1 卡片与批量生产力（第二 / 三波）

## 5. 并行与集成顺序

### 第一波：修核心错误

验收主窗口同时派发 A、B、C；自己负责只读复现、契约审计与提交检查。A/B 之间只约定一个“可嵌入紧凑编辑 surface”，不得同时修改对方拥有文件。

集成顺序：A → B → C。每条线都必须给独立 commit、测试数字、真实窗口结果和未完事项。

### 第二波：来源与语义

在第一波真人验收后启动 D 与 E；F 只做不依赖新 schema 的单卡 / 多选基础操作。E 的契约通过后，W2 / W1 再分别接正文引用和画布呈现。

集成顺序：D（无 schema 部分）→ E 契约 / 迁移 → W2 引用 UI → W1 关系呈现 → F。

### 第三波：长尾生产力

历史版本恢复、DOCX/PDF 导出、手写 / 荧光笔 / 橡皮擦分别做纵切，不以“按钮已出现”验收，必须从入口走到持久化 / 恢复或文件产物。

## 6. 真人验收场景

### 6.1 富文本

1. 新建含 5 个块的中文卡片；从第三块拖选到第一块并替换。
2. 在空段落 Backspace 合并上一块；在块尾 Delete 合并下一块。
3. Ctrl+A 选择全文；中文 IME 组合态不提前提交。
4. Paragraph → H1 → H6 → Paragraph；保存、关闭数据库、重开内容与格式一致。
5. 编辑时没有常驻绿色矩形；Focus 仍可通过克制边界 / 光标辨认。

### 6.2 白板

1. 双击空白，新 Card 原位获得焦点并输入；保存后进入全局卡片库。
2. 双击普通卡直接原位编辑；放大按钮才进入全屏编辑。
3. 四向锚点拖线；移动、缩放任一端后线实时跟随，重启仍正确。
4. 白板 Card 的中英文、数字字体与卡片库同一 Token。

### 6.3 视频

1. 导入用户给出的 `BV1E8KV6QEu7`，在 Windows Desktop 内播放；如不能研读，界面明确能力级别。
2. 导入无字幕音乐 MV，播放到任意位置直接建点标注，不经过字幕行。
3. 导入有 CC 的 YouTube 样例，选择轨道、cue seek、反向高亮、重启恢复。
4. 平台字幕失败时显示真实分类原因，并可导入 SRT/VTT 继续研读。

### 6.4 导入与小红书

1. 同一个“导入卡片”入口分别选择本地文件与链接。
2. 文件 / URL 自动识别，预览零写入，确认后只创建统一 Source / Version / Card。
3. 小红书卡片能显示安全缓存的原图；OCR 文本可搜索并能回到对应图片。
4. 重要评论有明确来源与抓取状态；拿不到时诚实为空，不造评论。

### 6.5 双链

1. 从卡片 A 引用卡片 B；A 可跳 B，B 显示来自 A 的反链。
2. 复制卡片链接粘入 C，生成引用而非复制 Card。
3. 块级链接可定位具体 block；卡片出现在不同白板仍是同一语义关系。

## 7. 测试与完成定义

每个工作包至少需要：

- 领域 / adapter 单测；
- 对应 Widget / 交互测试；
- 一条 Repository / 持久化 / 重启跨边界闭环；

- `flutter analyze` 定向零 error / warning；

验收主窗口不得把以下情况写成“完成”：

- 只能保存 Bilibili 链接但不能本地消费；
- 只有字幕行能建视频笔记；
- 连线看起来出现但不随 BoardItem 变化；
- 卡片双击弹出 Dialog 而非表面原位编辑；
- 每块单独可编辑但不能像连续文档操作；
- 只做双链按钮，没有反链查询和重启恢复；
- 小红书只显示 OCR 文本却没有原图证据。
