# schema6 电脑外备份与换机恢复（审核草案）

本轮只实现并验证合成备份/恢复源码，不读取原备份、不接触现役、不获取真实口令。原九类 52 文件真实只读恢复证据仍见[原交接](SCHEMA6_REAL_BACKUP_RESTORE_20261006.md)，不会把合成数据当成新的真实备份。

## 密钥与保管

备份键保留原 CurrentUser DPAPI 包，同时以固定参数 scrypt 派生口令键、AES256GCM 再包一份；格式和参数由工具检查，拒绝篡改和不受限 KDF。口令只经安全提示和一次性内存管道进入受验证子进程，不经过命令行、环境、明文文件或输出。口令包还须与 backupSetId、键身份和归档认证绑定配套，不依赖文件名猜测来源。

用户实际口令由 Lynx 在未来设置时自己输入、保管；本轮测试使用随机合成口令。建议密码管理器加电脑外的独立纸质/离线保管；不把口令与唯一备份同时留在一台会丢失的电脑。口令变更要重新包键并实际检查旧/新密文，不销毁最后一个可解开的包。

## 每天自动备份

在用户登录后的同一受保护会话运行，每次登录检查是否到期；之后检查距上次成功是否满 24 小时。默认保留 30 天，可配置。SQLite 用在线一致副本，其他输入逐项稳定读取；九类清单仍是显式清单，工具不能替人发现全部生产依赖，也不宣称多个库全局同一事务。

归档只读检查上下文取自那份一致副本；同时保存真实独立 custody，**不得用副本上下文替换现役 current-head、签发接管资格或激活检查副本**。失败只报告无正文原因，下次到期检查重试；不会因此停止仍健康的 Core。镜像根目录是可配置项，Lynx 后选 U 盘等位置；只复制已认证密文、口令包及绑定回执，不复制裸库或真实正文。

保留策略只处理工具自己创建、通过认证且到期的备份集；链接、未知目录、未完成归档不能当成成功归档，更不能顺手清理未知文件。外接介质断开时保留本机成功归档并报告镜像失败，介质重新可用后再补复制。关机先停备份托管进程树再等 Core 清停，未完成归档不算成功。

## 只用口令还原

1. 在新 Windows 用户/机器的**新受保护检查目录**放置固定验证工具与外部 manifest 锚，带入密文、口令包、认证绑定回执和完整备份清单。
2. 用 `portable_backup_schema6.ps1` 的 Password-only RestoreInspection 入口安全输入口令；不用原 DPAPI blob，不运行备份里的旧启动脚本。
3. 归档完整认证后才提取到新目录；运行真实 Core 的不可变只读检查。核 node_id、schema、设备、全部用户表数量及类型化指纹；业务写入/配对必须拒绝，退出后数据库字节不变、无新 sidecar。
4. 二次库、MCP OAuth/writeback/手机 feed 状态、i_memory policy/快照、隧道配置、手机副本逐项按原九类清单核验。仅成功解密或比哈希不等于恢复完成。
5. 检查恢复目录保持 inspection-only。换机现役接管还需新用户 DPAPI 包、独立恢复键/current-head、路径与配置绑定的受审转换，及实际网络/客户端验收；不翻角色、不恢复旧 head，不将一个旧库覆盖已经接受新写入的库。

本机当前只有当前用户会话，没有已获准的第二用户/第二机器测试环境；本轮做独立子进程、原 DPAPI 不可用的口令检查还原，**不称已经跨 Windows 账号/异机实测**。真正跨账号/换机 Gate 的步骤如上，需在相应环境由 Lynx 授权后执行；本轮不创建账号、不改现役权限或触碰手机。

## Tailscale：重新登录，同一机器名

Lynx 已决定不备份机器私钥；它不是待补的备份缺项。换机不要复制旧 `tailscaled.state`，以新身份登录原 tailnet。同一 tailnet 要求机器名唯一；旧设备仍占名称时，确认旧机不再服务后处理名称冲突，再给新电脑原机器名。机器名决定 MagicDNS 名称，数字 IP 不保证相同。参见[Tailscale 机器名文档](https://tailscale.com/docs/concepts/machine-names)。

恢复流程（本轮不执行）：

1. 新电脑安装 Tailscale，登录同一账号/tailnet；手机仍登录该 tailnet，无需因换电脑重装手机 App。
2. 确认设备身份和新 IP，设置原机器名；保留旧机器记录供核验，名称冲突由管理员处理。不要用复制机器私钥保住旧 IP。
3. 恢复 MCP 的本地 47860/47862 服务与认证文件，并核 `127.0.0.1:47862` 由正确 MCP 监听。未认证 `/v1/remember/changes` 应仍拒绝；不能为了恢复而关鉴权。
4. 依据备份中的 Serve **路径、协议、外端口**重建局部映射。例如原来的 remember 是 HTTPS→本地 47862 时使用相同的 `--https`/`--set-path` 指向 `http://127.0.0.1:47862`；若原来是 tailnet TCP47862，则配置 `--tcp=47862 tcp://127.0.0.1:47862`。不要同时新增两种映射或全量 reset 掉无关服务。用 `tailscale serve status --json` 对照原清单。Serve 参数须以实际备份为准，参见[官方命令](https://tailscale.com/docs/reference/tailscale-cli/serve)。
5. 手机若使用 `100.x` 地址，更新 Core 同步地址和旧 remember feed 的 47862 地址；若使用原 MagicDNS 名，核解析到新设备、端口/路径正确。MCP 手机拉取令牌若原 DPAPI 仅能在旧用户解开，则走受审重新签发与手机绑定，不借机改数据库设备身份或消息 sync_id。
6. 从手机验证 tailnet 可达及认证拒绝/成功边界，再检查旧 feed cursor、未 ack 记录、单一消费者；Core 同步另核单一上传器和既有队列去重。captures 真机闭环未过仍保留 47862。

Cloudflare 的公网隧道凭据与 Tailscale 机器身份不同；原隧道配置/凭据仍在九类加密备份中，换机按原服务清单核验后重建。不要把能 ping 到新机当成 MCP、手机消费或 Core 同步已经通过。
