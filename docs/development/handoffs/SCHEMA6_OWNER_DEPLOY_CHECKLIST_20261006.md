上线后：**正常关机自动请求安全停止；非正常退出后，下次登录自动检查和恢复，检查失败或迁移中断时需要处理。** Core 与 MCP 由同一个 Windows 交互式登录会话管理：Core 就绪后才启动 MCP；更新后的自动登录可能在你解锁前触发任务，本机行为尚不确定，见现场清单 ARSO 部分。电脑关机时手机/网页不能连到本机服务。

NTFS 是这次 U 盘镜像的**现场预检要求**，不是程序已有的文件系统专属错误提示。程序仍严格检查权限；镜像失败目前只给通用错误，i 会结合现场检查解释原因，不能把所有失败都说成 U 盘格式不对。

你每天直接正常关机即可，不需要说口令或等 i 在线。关机流程在同一个30秒总预算内，停止备份派发，确认 MCP 进程树和句柄释放，再结束活动备份，最后请求 Core 安全关闭。旧 MCP 以隐藏进程运行，Windows 下不能依赖 SIGTERM：最多等待3000毫秒后可强制结束会话拥有的 MCP Job，回执会明确写强制退出。Core 自己的 child/guardian 仍必须正常退出、无强杀并取得 `clean_closed` 和锁释放回执；不能混为“所有程序都优雅关闭”。系统强制终止或超时不能承诺 Core 清停，下次登录恢复前仍先清理会话拥有的 MCP 树，再加密保全和检查恢复。纯睡眠通常保留原进程，唤醒不另开实例。

MCP 将使用固定、同字节且有完整库存/hash保护的源码快照，继续使用现有可变 `.state`；源码与状态分开，不替换账本或重签 token。生产 prepare 必须带 MCP 配置，旧独立 MCP 任务不再自动启动；这些都是未来另获现场授权后的操作，本轮不注册或停用实际任务。

若下次登录后服务没有恢复：保持文件原样，联系 i；i 会读取本次 control 目录的停止、退出或恢复回执，说明原因和处理步骤。不要删 WAL、锁、标记，不要覆盖库或反复尝试旧版本。检查失败、独立 custody 回退、迁移中断才阻断启动。恢复日志只记录事件与校验结果，不记录聊天正文。

恢复口令保存在你自己的密码管理器，另留一份放在电脑外的安全地方；不要与唯一备份同放在会丢失的笔记本里。把**密文、口令包、认证绑定回执**一起复制到电脑外，旧包与完整清单也随加密备份保留。DPAPI 方便本机运行，恢复口令用于离开原 Windows 用户时的检查还原。忘记口令且原用户不可用时，这份密文无法解密。

换电脑时，目前可用口令还原到新检查目录并运行只读 Core 核验；**检查目录不能直接当现役库启动**。从备份新建现役 Core 所需的新用户 DPAPI、新的独立恢复 key/current-head、路径/配置绑定是**下一轮功能缺口，本轮不实现**。Tailscale 换机重新登录原账号、沿用机器名并重配服务；详细边界见[异机恢复说明](SCHEMA6_OFF_MACHINE_RECOVERY_20261006.md)。
