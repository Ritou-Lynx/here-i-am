# schema6 上线操作单｜给 Lynx 的审核草案

**本轮只更新 PR #14，完成后暂停等审核；不合并、不部署。** 现在仍由旧 Core 服务，下面的自动运行规则要等你批准切换、安装登录任务以后才生效。

上线后：**正常关机自动安全停止；非正常退出后，下次登录自动检查和恢复，只有检查失败或迁移中断时才需要处理。** Core 只在你登录 Windows 后运行；电脑关机时手机/网页不能连到本机服务。

| 步骤 | i 做什么／你看什么 | 预计停机与失败处理 |
|---|---|---|
| ① 审核与准备 | 核对 PR 的精确提交、全部绿色检查、六类合成演练、九类备份与恢复清单；保留调试邮件关闭方案。 | **0 分钟**。没有部署批准就继续旧版本。 |
| ② 保管恢复口令与外部备份 | 你在本机安全输入一次恢复口令；i 创建口令包，设置每天备份、默认保留 30 天，并把密文复制到你选的 U 盘等位置。 | **0 分钟**。口令不发给聊天、不进日志或仓库；目的地未选时先保持本机加密备份。 |
| ③ 约定切换窗口 | i 列出精确旧包、任务、端口、原库、消费者及退回点，你审核现场切换范围。MCP、手机安装分别审核。 | **0 分钟**。本页不直接签发停服务或安装批准。 |
| ④ 停旧 Core、保全原件 | 获准后冻结旧任务、结束绑定的进程树；在打开 SQLite 前加密保存原 DB/WAL/SHM/journal，确认所有 writer 已停。 | 预估 **5–15 分钟**。未完成就不迁移；原文件仍在，排除旧任务重复启动后可重开旧 v4。 |

你每天直接正常关机即可，不需要说口令或等 i 在线。关机钩子会请求安全关闭并等进程、Job、锁的完成回执；系统强制终止或超时不能承诺清停，但下次登录会先加密保全，再自动检查恢复。纯睡眠通常保留原进程，唤醒不另开实例。

若出现“需要处理”：保持文件原样，把提示中的**原因和回执编号**交给 i；不要删 WAL、锁、标记，不要覆盖库或反复尝试旧版本。检查失败、独立 custody 回退、迁移中断才阻断启动。恢复日志只记录事件与校验结果，不记录聊天正文。

恢复口令保存在你自己的密码管理器，另留一份放在电脑外的安全地方；不要与唯一备份同放在会丢失的笔记本里。把**密文、口令包、认证绑定回执**一起复制到电脑外，旧包与完整清单也随加密备份保留。DPAPI 方便本机运行，恢复口令用于离开原 Windows 用户时的检查还原。忘记口令且原用户不可用时，这份密文无法解密。

换电脑时：先在新机器用口令把备份还原到新检查目录，跑真实只读 Core，核 node_id、schema、设备和全部表指纹；确认后由 i 重新绑定新用户保管、配置路径和独立 custody，**检查还原目录不能直接当现役库启动**。Tailscale 不迁移机器私钥：重新登录原账号，释放旧机器名并给新电脑同名；按备份的服务清单重配 Serve。手机保持同一 tailnet，若原来用数字 IP，则更新 Core/47862 地址与必要令牌；用同名 MagicDNS 也要确认地址、端口与授权。详细步骤见[异机恢复说明](SCHEMA6_OFF_MACHINE_RECOVERY_20261006.md)。

本轮没有实际关机、创建/改动现役任务、换用户或换电脑。合成消息演练、独立口令检查还原与实际异机验收分开报告，详见[本轮验收](SCHEMA6_AUTOMATIC_MAIN_ACCEPTANCE_20261006.md)。
