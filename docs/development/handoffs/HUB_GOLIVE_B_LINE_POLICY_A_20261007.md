# B 线：网页 A 方案与 P1 源码闭合

## 用户决定与上线时间

2026-10-07 用户审核认可此前源码和测试质量，并将 P1 上线目标改为上海安顿后（约 2026-10-17 之后）。本轮只交付源码、测试、推送及 CI；不更换现役 schema6 包、不启用领域、不导入真实授权、不迁移真实记录、不切换 47862 消费者。

网页采用用户明确选择的 A 方案：

- `i_chat_turn phase=start` 仅返回本次确切用户原话已被 Core 接受后的 `user_message_anchor.sync_id`。等待重试或 assistant/end 不提供用户锚点，不查找“最近一句”补授权。
- MCP session 绑定一个明确对话；每次写回开始即清空旧锚点，只保存本次成功提交的用户锚点。RPC 内部注入线程和确切 sync_id，工具参数不能设置这两个内部字段；无绑定、跨线程、当前消息待提交均不能复用旧锚点提权。
- `i_remember` / 网页 `capture_add` 将该 sync_id 作为可选 `authorization_ref`。Core 核验自己保存的 user/chat 消息及配置的 origin、character、principal、installation 绑定；通过则按 `user_via_agent`。
- 同一线程出现后续回复或下一轮后，旧锚点不能授权新的操作；其他线程不会替换本线程的锚点。这里核验消息身份与轮次，用户原话的忠实转交仍是受授权网页 agent 的职责，不把消息存在等同于自然语言语义审查。
- 未提供、查不到或无法核验该锚点时按 `agent_inferred` 提交，不因缺少锚点拒绝新记录。领域范围、来源、正文校验、用户字段锁和冲突规则继续生效。
- 同一 op_id 的原始请求摘要保持不变，重试恢复首次结果。迟到的消息同步不能把已经接受的 inferred 操作提升为用户授权。
- 网页删除仅限本端 `claude_web` 且创建后没有用户字段修改的记录。处理器确认不算用户编辑。正文清除与下游用户修改保护沿用领域删除机制。
- Ed25519 `wua1` 模块和测试保留，正式宿主不启用，不作为 P1 前提。手机 UI 的 `uia1` HMAC 完整意图签名继续生效，对用户无额外签名操作。

## 四个缺口的源码落点

| 缺口 | 本轮落点 | 上线时仍需的真实动作 |
| --- | --- | --- |
| Core 正式宿主装配 | 独立 `personal_domain_server` 正式入口读取显式运行配置，使用 `i_core_server` 注入接口装配真实 hooks、dedup、手机 HMAC / 网页消息 verifier；私有 owner 状态由 Windows CurrentUser DPAPI 持久化 | 主窗口审核新入口、新包清单及发布流程，按目标时间安装并验证 |
| 网页授权 | 精确消息锚点、Core actor 判定、无锚点降级、删除保护、幂等恢复 | 配置独立 Web domain principal；网页 bridge 使用该领域凭据 |
| 手机领域授予与路由迁移 | owner CLI 显式授权；现有 Core 设置页导入/撤销领域授权并重建运行时；冻结清单、导出、导入证明、重新查询 Core 并原子提交/中止 | 保护传输授权文件；核对当前 Core 与安装实例；按清单执行已批准的迁移 |
| 47862 接管证明 | App 冻结 manifest → Core 明确旧记录冻结/采用 → 签名 proof → App 查询持久 op 与当前 record/tombstone → 原子 owner/route/baseline 提交 | 真正提交之前旧桥继续作为唯一消费者；不得用合成测试回执宣称现役接管 |

手机凭据轮换不会偷偷重绑定已提交的 owner/route。若代次变化导致历史绑定不匹配，路由会停止；跨代次续接需另有明确的绑定迁移证明。这不是首次 P1 接管的隐式步骤。

- Core 与 MCP 的专项回归覆盖 A 方案、真实授权验证、字段锁、删除、幂等和迁移。

- CI 增加 Linux 正式宿主测试，以及 Windows 的真实 DPAPI / 受限输出与宿主测试。完整 CI 结果以最终推送 SHA 的运行记录为准；本文件不将尚未完成的流水线声明为成功。
