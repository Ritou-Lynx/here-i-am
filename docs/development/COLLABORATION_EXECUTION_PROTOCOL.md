# Here I am 项目协作执行协议

> 状态：生效；2026-09-05 按 GPT-6 Astra 指导精简。
> 负责规划、委派、回收和验收；产品与共享领域边界仍由根 AGENTS.md 和专项契约决定。

## 1. 按任务规模使用流程

常规修复、审计、文档优化和可在当前任务闭环的工作，直接用短 Plan 推进；步骤多或用了子 Agent，本身不构成创建 Goal、开新任务或等待用户的理由。

跨工作包/Worktree 或已有阶段验收的工作，用本协议记录依赖、所有权和交付证据。只有用户明确要求创建或执行已确认的阶段 Goal 时才使用 Goal 工具；不能从普通任务推断出新活动 Goal。已有 Goal 的范围与真人 Gate 不因流程精简改变。

## 2. Roadmap、Goal 与 Plan

- **Roadmap** 保存长期方向、依赖和阶段进入/退出条件。产品入口是 `docs/companion-first/PRODUCT_ROADMAP.md`；只在优先级、基线或依赖事实改变时更新。
- **Goal** 保存用户确认的结果、基线、完成标准、工作包、边界、必要自动/真人 Gate 与失败去向。状态页位于 `docs/development/goals/<goal-id>.md`，模板见该目录 README。
- **Plan** 保存当前执行顺序，可在授权范围随证据调整，不逐步重批。改变产品语义、权限、已确认完成定义或外部影响时先取得对应决定。
- “先给草案，不改代码”或“先等我确认”只交付要求的草案；“创建 Goal，按协议执行并派发”授权已确认范围内的内部委派、必要独立任务/Worktree、本地集成与列明验证，不附带 push、发布或扩展范围。
- 任务中途的新消息先作为补充/纠正；回答侧问后继续已有目标，除非用户明确取消或换成不兼容目标。

## 3. 主 Agent 与并行选择

主 Agent 负责最终结果、架构取舍、关键路径、集成与验收，可直接实现需要紧密上下文的工作，不必限制为派发管理员。模型路由只引用根 AGENTS.md，不在工作包模板重复固定模型。

**子 Agent** 用于独立搜索、审计、实现或验证，有明确产出且并行能节省时间或改善质量时使用。父任务保留边界和上下文，worker 返回精炼证据。不因使用子 Agent 就新增用户侧任务或阶段 Goal。

**独立 Codex 任务** 仅在用户明确要求新任务，或已用上述阶段派发指令授权时创建；适合需要独立持续跟进的工作。Worktree 是文件隔离方式，不强制创建侧边栏任务。使用工具的真实参数，不把 queued clientThreadId 当成已就绪 threadId。

派发后主 Agent 继续独立工作，结果就绪即可复核和推进对应依赖；不要等全体 worker 返回才处理第一个结果。最终交付前收齐影响完成判定的结果。失去必要性的工作显式取消并记录，不留下后台工作后声称完成。

## 4. 所有权与共享边界

- 从用户指定基线开始；未指定时用已核实的本地 `v3-lab`。记录精确 commit，不擅自 pull 追逐“最新”。
- 真并行写入使用隔离 Worktree / `codex/<task>` 分支；同一目录只顺序写，或由主 Agent 明确分配互不重叠文件。禁止同时改同一共享文档或 Git 索引。
- schema、根依赖、生成文件、最终格式化与候选构建由集成主 Agent 串行处理；独立读取和不争用输出/设备的测试可并行。
- 保留已有 staged / unstaged 修改；worker 只提交获授权范围。提交不是普通子 Agent 的默认必需项，必须有既有授权。
- 产品/数据/权限边界变更由主 Agent 复核。缺少用户决定的部分暂停，独立工作继续；工具能力、沙箱或配额失败分别诊断。
- 白板 Card / Source / Anchor / Snapshot / PlayerAdapter 共享语义与 W0 所有权遵守白板总纲。

## 5. 派发与回收

每份委派只给足以下信息，不复制 AGENTS、产品历史或日志：

```text
目标与完成标准：
输入/权威资料/精确基线：
允许修改的路径；共享契约影响：
必要验证与外部动作边界：
返回：结论、文件/行号或最小 diff、验证、限制与未完事项。
```

子 Agent 显式选择模型/effort，默认最小上下文；需要近期对话才附带。默认不再派生；进一步拆分由主 Agent 安排。不要求当前工具不支持的 follow-up 模型参数；需要换模型时用受支持方式重新派发窄任务。

独立任务另记 task/thread ID、host（如有）、分支、Worktree、交付 commit 与相对 handoff。阶段派发已授权提交的工作包，必须 commit + handoff 才能集成；只读审计无须制造空提交。只有用户明确指定新任务模型时才给 create_thread 的 model/thinking；普通内部子 Agent 使用上述显式分层，不混用两套接口。

主 Agent 用紧凑等待/状态工具回收，不反复读完整历史。worker 求确认时先查既有授权及规则是否适用；已授权的常规决定直接解决，仍缺用户决定时说明具体事项与来源，不机械转发重复审批。

二审核查真实 diff、关键断言与验证，不采信一句“已完成”。返修优先带具体证据交回原工作包，无上下文重开只在必要时使用。

## 6. 最小可恢复状态

普通任务使用当前 Plan 和最终交付。多包工作/已有 Goal 保留足以恢复的表：

| 工作包 | 执行者/任务 ID | 基线与拥有路径 | 状态 | 交付与证据 | 下一步 |
|---|---|---|---|---|---|
| 示例 | 主 Agent / 子任务名 / thread ID | commit、分支/Worktree、路径 | 进行中 | commit/diff、handoff、检查结果 | 具体动作 |

状态可用“待执行、进行中、阻塞、已验证”；真实集成、构建、真人 Gate 分别记录，不能把“已验证”解释成全部通过。现存 Goal 的详细状态和历史证据保留，不批量改写。

在派发、阻塞、交付/集成或 Gate 结果改变时更新，相同轮询不写流水账。worker 只写自身 handoff；其已授权的隔离提交可按根 AGENTS 使用一次性 `SKIP_PROJECT_STATE=1` 例外。主 Agent 实际集成后统一更新项目状态、DEVLOG、必要 Roadmap，保留候选证据边界并正常通过状态 hook。

## 7. 集成、验证与结束

1. 复核范围、基线、修改与共享契约；已有 Goal 继续按原完成定义执行。
2. 一次选择性集成一个写工作包；保留可追溯提交/差异和恢复路径。
3. 跑相应专项检查，跨模块变更再增加组合回归。通过后仅因新改动、失败或未解风险扩展测试。推送任务分支后以 GitHub CI 为组合回归与 Windows 构建的权威结果，失败直接在原分支返修。
4. 需要 App 候选或明确端到端 Gate 时再构建。Flutter build 前执行关键修复检查；Android 只用 hereIAmV3。纯文档/静态审计不强制构建。
5. 验收按[无人值守验证](UNATTENDED_VERIFICATION.md)分层：客观项（数据、Receipt/Undo、生命周期、恢复、清理）写成自动场景并在每个候选上重跑，一次跑完全部场景再汇总；真人只看主观项，每个里程碑一次，基于自动报告、截图或录屏异步给结论。真人结论按受影响路径沿用或重看，自动测试不能代替主观项的真人判断。
6. 整理结果、验证、限制与剩余决定，完成所有必要工作才标记完成；push/发布依明确授权执行，不把未授权 push 列为本地开发完成必需项。
7. 临时分支/Worktree 仅在确认安全回收且有授权时清理，不以关闭任务为由删除。
8. 主 Agent 依根 AGENTS 收口文档和 i closeout；独立已注册任务的交接只描述自身交付，不提前宣称主项目已集成。

上下文压缩、多回合或 Goal 结束本身不要求换主窗。先用状态和 handoff 恢复；只有用户要求、环境迁移或真实连续性失效时交接，保存待收 worker 与精确基线。
