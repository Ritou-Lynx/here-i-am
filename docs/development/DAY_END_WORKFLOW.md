# 日终工作流

触发：用户说“收工检查”“日终检查”“closeout”“day-end check”。此流程管理 Git 工作收尾；自动 i_close_session 不触发整套日终检查。

## 默认：只检查

1. 查看分支、HEAD、staged / unstaged diff，区分本轮成果与已有/其他任务修改。
2. 标出不应提交的凭据、真实数据库、手机 dump、日志、构建产物和临时文件，不读取或展示其私密正文。
3. 按事实判断是否需要更新项目状态；归纳可提交分组及消息。
4. 复用当前基线已有验证；新增/未覆盖变更才运行相关检查。文档核对链接与 diff，逻辑改动跑专项测试，跨模块影响再扩大。需要候选时才构建。
5. 简洁报告成果、检查结果、未验部分和建议提交范围，然后结束。

“只检查”不授权 commit、push、删除或清理。同一请求已明确授权某组提交/推送时直接执行对应阶段，无须再次确认。

## 提交 / 推送模式

- 复核精确范围，只 stage 授权文件/片段，保留无关 staged 与 unstaged 状态，不用 git add .。
- 有源定义变更时可纳入必要 Drift/本地化生成输出，不一律排除生成文件，也不手改。
- 按根 AGENTS 更新并同组提交必要状态，遵守 hooks。已有验证覆盖最终内容时，不重复全套检查。
- 仅 commit 授权范围；用户请求 push 才推送相应分支。普通提交不自动发布。
- 混合文件先准备可复核片段分组；只有无法判断归属或用户选择会改变内容时才询问，不因工作树脏就整体停工。

分支、Worktree、Android flavor、构建前检查与安装规则统一见根 AGENTS.md。保留用户无关修改，不把本流程当作 rebase upstream、清空工作树或清理历史的授权。
