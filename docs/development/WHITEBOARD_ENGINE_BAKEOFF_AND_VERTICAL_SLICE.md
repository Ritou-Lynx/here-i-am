# 白板引擎赛马与第一条纵向闭环

> 状态：Phase 0 桌面壳已完成；引擎赛马与领域纵切仍待执行
> 日期：2026-08-14
> 产品与数据契约：`docs/design/whiteboard-ui-spine-contract.md`

## 1. 目的

2026-08-14 已先完成 `desktop/whiteboard_mvp/` 的可丢弃桌面壳，用来验证首页密度、卡片库预览、白板进入 / 摆放 / 保存恢复和 `Card / Board / BoardItem / viewport` 数据边界。该壳不实现分组、连线、框选、撤销栈或 500 卡性能门槛，因此**不计作候选引擎赛马，也不构成生产引擎选择**；后续仍按本文统一 fixture 和硬门槛执行。

不直接开始“完整白板 MVP”。先用同一份数据、同一套交互和同一组验收条件，让候选引擎各做一个可丢弃试验，再选底座。选定后只实现一条真实纵向闭环：

**导入 TXT / EPUB → 进入唯一卡片库 → 放入白板 → 打开阅读 → 选中文字 → 用户 / 林埃分别批注 → 返回白板 → 重启恢复。**

这条闭环同时验证白板、阅读器、锚点、归属、持久化和林埃操作权限，信息量比先堆十种卡片更高。

## 2. 候选与约束

首轮只比较三类候选：

1. **AFFiNE 可复用部分**：验证成熟白板能力能否拆出并受自有数据模型控制；
2. **BlockSuite**：验证 block / edgeless 能否适配“卡片内容与白板摆放分离”；
3. **tldraw + 自有内容编辑器**：验证画布完全可控时，自建卡片与消费视图的成本。

如许可证、运行环境或仓库现状使其中一项无法合法、稳定地进入产品，记录证据后淘汰，不为凑齐三项绕过限制。

试验不是生产实现：

- 不接 Memory V3；
- 不迁移现有数据库；
- 不写正式同步；
- 不深做视觉皮肤；
- 不把候选引擎序列化格式确立为产品真相。

## 3. 统一适配边界

每个候选只允许通过适配层接触统一快照：

```text
WhiteboardSnapshot
  boards[]
  cards[]
  boardItems[]
  groups[] + groupMembers[]
  edges[]
```

必须实现：

- `load(snapshot)`：渲染同一份测试数据；
- `exportSnapshot()`：导出回统一结构；
- `onOperation(operation)`：上报放置、移动、缩放、分组、连线和删除；
- `setReadonly(bool)`：支持只读检查；
- `focusItem(itemId)`：从搜索、双链或消费视图返回时定位。

引擎私有节点 ID 只能保存在适配映射或可丢弃 view state 中，不能替代 `card_id / item_id / group_id / edge_id`。

## 4. 统一测试画板

每个候选必须载入相同固定数据集：

- 500 张卡：文字 220、书籍 60、图片 100、网页 60、批注 60；
- 20 个显式分组，其中 5 个折叠；
- 320 条边，其中一部分有方向、语义类型和标签；
- 30 张卡同时出现在另一张白板；
- 20 张高分辨率图片只载缩略图；
- 1 个 100 张卡的框选批量移动场景。

再追加 1,000 张卡压力档，只用于观察退化曲线，不要求首版长期舒适编辑 1,000 张同时可见卡片。

## 5. 必测动作

1. 冷启动打开 500 卡画板；
2. 连续缩放、平移并快速跨越密集区；
3. 单卡拖动、缩放与层级调整；
4. 框选 100 张卡并整体移动；
5. 建组、改组名、折叠、展开、解组；
6. 新建和编辑带标签连线；
7. 打开书籍卡进入阅读器，再返回并恢复位置；
8. 从全局搜索定位画板上的卡；
9. 导出快照、完全销毁画布、重新载入并做结构等价比较；
10. 撤销 / 重做连续 20 个混合操作；
11. 模拟林埃一次授权后的批量分组与连线，检查审计与整体撤销；
12. 在桌面窗口缩放和常见分辨率下检查悬浮面板遮挡。

## 6. 评分与硬门槛

### 6.1 硬门槛

任一项失败即不进入生产候选：

- 可合法用于目标产品，许可证和依赖链可接受；
- 能由自有稳定 ID 驱动，不强迫业务模型服从引擎私有文档树；
- 卡片内容与白板布局可分离；
- 能实现扁平画布、显式分组、连线、跨白板引用；
- 500 卡场景可持续交互，无明显长时间冻结；
- 快照往返不丢卡片、成员关系、边和布局；
- 可以定制全屏无常驻栏的交互壳；
- 离线可运行，不依赖厂商云才能保存或打开。

### 6.2 加权评分

| 维度 | 权重 | 观察内容 |
|---|---:|---|
| 数据模型可控性 | 25 | 自有 ID、快照往返、迁移难度、是否锁死私有格式 |
| 大画布性能 | 20 | 首开、平移缩放、批量选择、图片虚拟化 |
| 核心交互成熟度 | 15 | 选择、分组、连线、撤销、快捷键、触控板 |
| 自定义卡片 / 消费视图 | 15 | 书籍卡、批注卡、预览层与返回定位 |
| 可维护性 | 10 | 活跃度、代码复杂度、升级和 fork 成本 |
| 桌面集成 | 10 | 窗口、剪贴板、拖放、文件导入、离线打包 |
| 无障碍与输入 | 5 | 键盘、缩放、中文输入、可访问性基础 |

总分只在全部硬门槛通过后使用。相差 5 分以内时，优先选择数据模型更可控、维护面更小的方案。

## 7. 记录格式

每个候选最终只交一份短报告：

- 版本 / commit / 许可证；
- 适配了哪些统一动作；
- 硬门槛逐项通过或失败的证据；
- 500 / 1,000 卡的首开、交互与内存结果；
- 快照往返 diff；
- 最难定制的三件事；
- 若生产化，预计必须长期维护的 fork 面；
- 推荐：采用 / 保留备选 / 淘汰。

最终用 ADR 记录选型，不把试验分支直接合并为生产代码。

## 8. 第一条纵向闭环

### 8.1 范围

选定引擎后，只实现以下链路：

1. 用户导入一份 TXT 或 EPUB；
2. 核心创建 `SourceContent / SourceVersion` 和一张 source Card；
3. 卡片出现在唯一卡片库的“书籍”筛选中；
4. 用户把卡片放入白板，形成 `BoardItem`；
5. 点击卡片打开现有小说阅读器适配后的消费视图；
6. 用户选择文字，消费视图只提交标准 `Anchor` 位置；
7. 用户创建自己的批注卡；
8. 用户授权林埃在本次阅读中操作，林埃可在同一锚点创建独立批注卡；
9. 返回白板，书籍卡显示批注数量与双方归属提示，不在卡面展开全文；
10. 关闭并重开应用，原件、卡片、布局、锚点和批注全部恢复；
11. 将同一卡片放进第二张白板，验证不复制原件与批注；
12. 删除第二张白板中的摆放，验证第一张白板与原件不受影响。

### 8.2 明确不做

- 暂不做 PDF、图片区域、网页快照和视频时间轴；
- 暂不做任务房间完整 UI，只保留 `task_id` 适配边界；
- 暂不让林埃自主大规模整理整个卡片库；
- 暂不做多人共享；
- 暂不把批注自动提升为 Memory V3。

### 8.3 验收用例

- 同一锚点同时显示用户和林埃的批注，修改其中一条不影响另一条；
- 纯划线可以没有正文，并且不会出现在 User-truth；
- 文本版本变化时旧锚点不会悄悄跳到错误段落；
- 引擎快照损坏或升级时，能够从核心领域数据重建画布；
- 林埃越权操作被拒绝；授权内操作可连续执行并整体撤销；
- 所有跨实体引用只用稳定 ID，不引用某台设备路径或本机自增 ID。

## 9. 执行顺序与停点

1. **冻结契约**：评审 `whiteboard-ui-spine-contract.md`，只修语义矛盾；
2. **准备固定 fixture 与结构等价检查**；
3. **三候选短赛马**：每项设置相同时间盒，不做视觉润色；
4. **写 ADR 并选定一个引擎**；
5. **先落领域模型与核心 change contract**；
6. **接入引擎适配器**；
7. **完成 TXT / EPUB 纵向闭环**；
8. **再决定下一种媒介，优先图片或 PDF，不同时扩四种视图**。

停点规则：如果任何候选都无法同时通过“数据可控 + 500 卡可用 + 快照无损”，停止写生产白板，先缩小引擎职责或重做适配边界，不能靠把引擎私有 JSON 升格为产品数据库来赶进度。
