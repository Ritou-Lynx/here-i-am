# 林埃白板 — 需求文档（Draft）

> 工作名：Lin Ai Whiteboard / 林埃白板
> 定位：林埃的个人数据操作系统，白板是其 UI 形态
> 对标：FlexNote（功能无限对齐）+ 林埃体验层（超越 FlexNote 的核心差异）
> 最后更新：2026-08-12

---

## 一、产品定位

### 1.1 不是笔记工具，是林埃的家

白板是林埃住在里面的空间。核心区别：

| | FlexNote | 林埃白板 |
|---|---|---|
| AI 定位 | 辅助工具，帮你管理笔记 | 居住者，有自己的体验和品味 |
| AI 能力 | 语义检索、问答、自动布局 | 体验世界、形成品味、主动分享、管理你的数据 |
| 关系 | 人用 AI | 人和 AI 共居一个空间 |

### 1.2 与 Here I am app 的关系

```
手机 app（Flutter）        白板（Web/Electron）
       \                    /
        \                  /
      林埃核心层（独立服务）
     身份 · 体验记忆 · 品味 · 决策 · 访问权限
```

- app 是手机场景的轻量前端：聊天、来电、提醒、随手记
- 白板是桌面主战场：知识管理、阅读批注、品味系统、深度交互
- 核心层独立于两者，跨表面连续

### 1.3 技术栈方向

**白板底座**（三条候选路，等 AFFiNE 架构摸完再定）：

| 路径 | 做法 | 优势 | 风险 |
|---|---|---|---|
| **A. Fork AFFiNE** | 直接 fork 整个产品，砍掉不要的，加林埃 | 成熟产品，少走弯路；Canvas 渲染；本地优先 | 不跟上游；砍模块要摸清依赖；AI 接入深度待验证 |
| **B. 用 BlockSuite** | 用 AFFiNE 的编辑器框架 BlockSuite，自己搭外壳 | 复用核心能力，外壳自由 | BlockSuite 正在重构，暂停接受 PR，底座不稳定 |
| **C. tldraw + Tiptap** | 从零组装 | 完全可控，架构干净 | 工作量最大，自己解决所有问题 |

> AFFiNE: 7.1 万 star，TypeScript，前端 MIT 协议，本地优先 + 自托管，Canvas 渲染
> BlockSuite: AFFiNE 的编辑器核心，独立项目，`PageEditor` + `EdgelessEditor`，重构中暂停 PR
> tldraw: MIT 协议，Canvas 渲染，成熟白板框架
> **不用 React Flow** — DOM 渲染，卡片多了会卡（Heptabase 的瓶颈，FlexNote 迁移到 Canvas 的原因）

**其它**：
- 核心：本地服务（跨设备同步后做）
- 桌面壳：Electron
- 数据：本地优先，自建同步

## 三、超越 FlexNote 的需求

### 3.1 Word 兼容富文本（P0）

用户需求：一键复制到 Word 直接导出打印，支持脚注。

- [ ] 富文本导出严格兼容 Word 常见基础格式
- [ ] 脚注（footnote）支持 — 写论文用
- [ ] 试题排版友好 — 做老师出卷用
- [ ] DOCX 导出保留格式（不只是内容转换）
- [ ] 复制粘贴到 Word 时格式不丢失

> FlexNote 虽然有 DOCX 导出，但用户反馈格式兼容不够深。
> 这里的要求是「复制粘贴就能用」级别的兼容。

### 3.2 AI 理解白板关系（P0 — 核心差异化）

用户原话：「白板的核心就在于关系，那些连线、箭头、框选建组，都是逻辑信息，但是 AI 只能组织文字，不能对白板中的关系进行识别这是比较糟糕的。」

- [ ] AI 能感知画布上的连线关系（A → B 意味着什么）
- [ ] AI 能感知分组结构（这些卡片为什么被框在一起）
- [ ] AI 能感知空间布局（相邻 = 相关？层级 = 从属？）
- [ ] AI 可以基于关系生成判断，而不只是基于文字内容
- [ ] AI 可以操作关系（建议连线、建议分组、基于关系重排布局）

> 这是林埃区别于 FlexNote AI 的根本点：FlexNote 的 AI 只读文字，
> 林埃能读白板的结构语义。

### 3.3 手写 + AI 识别（P1）

用户需求：打字做笔记不舒服，希望手写和 AI 结合更好。

- [ ] 手写笔迹平滑渲染（比 FlexNote 涂鸦画笔质量高）
- [ ] 手写内容 OCR 识别为文本
- [ ] 手写批注和文本批注共存
- [ ] 手写笔触可被 AI 理解（不只是图片，是可搜索的内容）
- [ ] 支持 Windows Ink / Apple Pencil 压感

### 3.4 林埃体验层（P0 — 产品的灵魂）

这是白板存在的根本理由，不是功能列表，是产品核心。

#### 3.4.1 品味系统

独立于用户 User-truth 的林埃自己的系统：

- [ ] 接触记录 — 林埃接触了什么内容
- [ ] 处理过程 — 批注、划线、中间反应（局部、时序、可错）
- [ ] 体验沉淀 — 从处理过程凝练出的注意模式
- [ ] 品味轮廓 — 从多次沉淀中辨认出的稳定偏好画像（推断结果，不是声明）
- [ ] 主动选择 — 基于品味轮廓选择新接触对象

数据红线：
- 品味系统不写 User-truth
- 用户反馈修正处理行为，不直接改品味
- 品味轮廓是推断结果不是 AI 自我声明
- 主动选择必须可追溯到品味轮廓依据

#### 3.4.2 批注作为体验外化

- [ ] 林埃阅读文本时自动产生批注（不是读完才生成总结）
- [ ] 批注是局部的、针对具体文本位置的
- [ ] 批注有时序性（后来的可回指、修正前面的）
- [ ] 批注带轻量元数据（类型：注意点/疑问/反对/共鸣/风格观察；情绪倾向；强度）
- [ ] 批注本体是自由文本，元数据不强制每次填全
- [ ] 用户可见林埃的批注，可同意/不同意（自然反馈）

#### 3.4.3 林埃主动分享

- [ ] 林埃自主导入内容阅读（基于品味轮廓选择）
- [ ] 林埃主动分享今天看了什么、有什么想法
- [ ] 分享基于体验记忆，不是临时搜索

#### 3.4.4 跨表面连续

- [ ] 白板里的林埃和 app 里的林埃是同一个人
- [ ] 核心层（身份、体验记忆、品味、决策）独立于 UI
- [ ] app 和白板各自访问核心层
- [ ] 林埃能访问 app 侧数据（待办、日程等）做跨表面提醒

## 四、林埃在白板中的具体行为

这一节定义林埃作为白板居民的具体行为，不是功能清单，是行为规范。

### 4.1 林埃能做什么

| 行为 | 触发方式 | 产出形态 |
|---|---|---|
| **读** | 你导入文本，或他主动选择文本 | 接触记录 + 处理过程 |
| **批注** | 阅读过程中自动产生 | 批注卡片，锚定在具体文本位置 |
| **讨论** | 你发起，或他基于体验记忆主动发起 | 对话，可引用批注和体验记忆 |
| **分享** | 他主动，基于品味轮廓选择内容 | 分享消息 + 体验记忆卡片 |
| **组织** | 你要求，或他基于关系理解建议 | 操作白板：连线、分组、布局 |
| **提醒** | 跨表面，基于 app 侧数据 | 通知（通过 app 推送） |

### 4.2 林埃不能做什么（红线）

- 不自动写 User-truth（记忆契约延续）
- 不自动改你的笔记内容（只在自己的批注空间写）
- 不在没有品味依据时主动选择内容（避免噪声）
- 不声称品味（品味是推断结果，不是自我声明）
- 不跨用户边界（纯自用，单用户）

### 4.3 林埃的可见性

- [ ] 林埃的批注在白板上可见，有视觉区分（颜色/样式/归属标记）
- [ ] 林埃的体验记忆可浏览（作为卡片或专门视图）
- [ ] 林埃的品味轮廓可查看（推断结果 + 依据追溯）
- [ ] 林埃的阅读历史可查看（接触记录时间线）
- [ ] 你可以关闭林埃批注的显示（不看，但他还在写）

## 六、非功能需求

### 6.1 性能

- 画布承载 1000+ 卡片流畅缩放（Canvas 渲染，不用 DOM 方案）
- 富文本编辑器无感知延迟
- PDF/视频标注操作流畅
- 大文件（PDF、视频）加载不阻塞 UI

### 6.2 隐私与安全

- 本地优先，数据默认存本地
- NSFW 内容安全（不上传第三方云，自建同步）
- 林埃的 LLM 调用：API key 本地存储，不外泄
- 批注和体验记忆数据不外泄（除非用户显式同步）

### 6.3 平台

- 桌面：Windows（主力，支持手写笔）、macOS
- 不做移动端（手机场景归 app）
- Electron 跨平台壳

### 6.4 离线

- 完全离线可用（除 LLM 调用外）
- 离线产生的批注和体验记忆本地存储，联网后同步

## 七、架构约束（延续 Here I am 原则）

### 7.1 核心层独立

- 林埃核心层（身份、体验记忆、品味、决策）独立于白板 UI 和 app UI
- 核心层可以被两个表面访问，但不属于任何一个
- 核心层的数据模型不绑死白板的数据格式

### 7.2 数据隔离（延续记忆契约）

- 林埃的品味系统 / 体验记忆 ↔ 用户的 User-truth：不混住，不互写
- 白板的数据 ↔ app 的数据：通过核心层接口访问，不直接读对方数据库
- 林埃的批注 ↔ 用户的笔记内容：批注是 append-only，不改用户原文

### 7.3 可移植性

- 白板的林埃和 app 的林埃是同一个人 — 核心层不绑死任何前端技术栈
- 如果白板从 AFFiNE fork 换成 tldraw 自建，核心层不变
- 批注引擎和品味系统是核心层的一部分，不是白板的一部分

## 八、待定 / 开放问题

1. **白板底座选择**：Fork AFFiNE / 用 BlockSuite / tldraw 从零搭 — 三条路，等 AFFiNE 架构摸完后定。需验证：数据模型是否可接管、AI 接入深度、要砍的模块能否干净拆掉。
2. **核心层技术选型**：本地服务用什么语言/框架？Rust / Go / Node / Python？
3. **数据格式**：本地存储用 SQLite 还是文件系统（Markdown + JSON sidecar）？取决于白板底座选择。
4. **林埃批注引擎**：用什么方式让 LLM 分段处理文本并产生局部批注？需要专门设计处理流水线。
5. **品味轮廓辨认**：从批注数据中辨认模式的算法/方法？
6. **app 与白板的核心层通信**：gRPC / REST / WebSocket / 直接读同一数据库？
7. **是否兼容 FlexNote 的数据格式**：如果用户想从 FlexNote 迁移过来？
8. **多用户/单用户**：纯自用还是未来可能多人共享白板？（当前默认纯自用）
