# Here I Am UI System Roadmap

本文档用于把当前视觉方案推进成可套用到整个软件的 UI 系统。它不替代
`here-i-am-ui-design.md` 的概念设定，而是把概念拆成可验证、可实现、可验收的工作顺序。

## 已确定的设计资产

- 色调：当前默认锁定为暮雨玫瑰 / Dusky Rose Rain；R0-R7 与紫色、暖色候选保留为后续换肤参考。
- 材质：玻璃、雾、水汽、气泡、凝露卡；暮雨玫瑰叠加静态雨滴玻璃贴层。
- 核心动效语义：坠落、记忆沉入、水波展开、卡片凝结出现。
- 记忆点形象：透明气泡，文字与泡心哈气雾绑定。
- L3 -> L4：点按气泡触发水波，气泡不破裂消失，卡片凝结出来。
- L4 卡片：厚雾玻璃 / 凝露水痕 / 窗影 / 轻微 3D 入场。

## 尚未锁定的问题

- 圆柱大厅是否作为正式主导航形态，还是先作为 Life Space 的高级视觉层。
- 圆柱屏每屏宽度、弧度、屏缝、材质、抬头可见内容。
- 聊天界面最终结构：消息流、输入区、圆环、记忆提示、背景世界之间的层级。
- 坠落和回程动画的完整节奏。
- 记忆云坐标系是否正式绑定数据结构，还是先作为视觉投影规则。
- 复杂手势是否进入第一版，或先用显式按钮/轻手势替代。
- 凝露卡信息容量、操作键、滚动方式。

## 工作原则

1. 先系统，后页面。
   先定 token、组件、状态和动效语义，再改具体页面。

2. 先产品可用，后沉浸完整。
   第一版不追求完整 3D 世界，而是保证聊天、记忆审核、卡片、设置等真实流程能用。

3. 世界层和系统层分开。
   聊天、记忆、Life Space 可以沉浸；设置、权限、模型配置要清楚、稳定、低装饰。

4. 能力留在对话，产物进入仪表。
   新功能先判断它留下什么产物，再决定进入哪个屏。

5. 坐标系先作为视觉规则。
   在数据模型没有验证前，不把情绪极坐标强行写死进底层结构。

6. 第一版保留点击交互。
   现有 Chat 功能全部保留；圆柱、记忆云、捏合、空间漫游等 3D 交互先作为后续增强，不作为第一版主路径。

7. 雨滴层只做静态材质。
   它是暮雨玫瑰主题的玻璃贴层，不做动态天气特效；实现时不得引入 canvas、requestAnimationFrame、keyframes 或持续动画，也不要画成平行竖线、水痕或划痕。

## 阶段 1：UI 系统规范

目标：把视觉方案翻译成可复用规则。

产出：
- `UI_SYSTEM_SPEC.md`
- 色彩 token
- 材质 token
- 字体和间距规则
- 动效语义表
- 可用 / 不可用视觉规则
- 世界层、产品层、系统层的适用范围

验收：
- 新增一个页面时，能根据规范判断该用什么色、什么卡、什么动效。
- 不需要回到概念文档重新解释“这个按钮为什么这样画”。

## 阶段 2：功能板块映射

目标：把现有软件功能映射到新的世界结构。

产出：
- `FEATURE_UI_MAP.md`
- Chat / Life Space / Memory Review / Schedule / Personal / Settings 的归属表。
- 每个功能的页面模式、核心组件、状态、操作。

重点问题：
- 聊天是不是唯一操作入口。
- 当前 `CompanionLifeSpaceScreen` 如何改造成观察面。
- `SharedLifeMemory` 如何分成“质检台”和“记忆云”两种 UI。
- 旧 Memex timeline 是否继续作为 Review 的一部分，还是退居兼容入口。

验收：
- 每个已有功能都有明确归属。
- 新功能可以用“生活产物”规则判断落点。
- Chat 现有能力没有因为视觉重设计而丢失。

## 阶段 3：核心状态机与交互灰盒

目标：把层级和动效整理成可验证状态机。

主状态：
`Chat -> Falling -> Hall -> Cloud -> Card`

产出：
- `INTERACTION_STATE_MACHINE.md`
- 进入 / 返回 / 手势 / 按钮 / 降级交互规则。
- 移动端优先的灰盒原型验收清单。

重点问题：
- 圆柱大厅是否进入第一版。
- 捏合手势是否为主交互，或仅作为增强手势。
- 回程动画如何不破坏“坠落”的语义。

验收：
- 用户在每一层都知道自己在哪里、能做什么、怎么返回。
- 没有横滑/竖滑/捏合冲突。

## 阶段 4：Flutter 设计基础设施

目标：把设计系统接入代码。

建议新增或改造：
- `AppColors` / `HereIamColors`
- `AppTextStyles` / `HereIamText`
- `AppSpacing`
- `AppRadius`
- `AppMotion`
- `HereIamTheme`

第一批基础组件：
- `HereIamScaffold`
- `PresenceRing`
- `DewCard`
- `RippleReveal`
- `CompanionGlassSurface`
- `LivingDashboardPanel`
- `MemoryReviewItem`

验收：
- 新组件能被 Chat 和 Life Space 复用。
- 不在页面里散写颜色、圆角、阴影和动效时长。

## 阶段 5：页面落地顺序

1. Chat home
   - 新背景层
   - 中央存在圆环
   - 聊天消息和输入区重排
   - 记忆沉淀提示

2. Memory Review
   - 今日 / 本周质检台
   - 对 / 改 / 撤
   - 点亮云中对应记忆的预留接口

3. Dew Card
   - 记忆详情
   - 情绪 / 来源 / 时间 / 操作
   - 可审计、可纠正入口

4. Life Space shell
   - 先做 2.5D 仪表盘
   - 再评估圆柱大厅正式化

5. Settings hatch
   - 入口可以有世界感
   - 内部保持普通、清晰、稳定

## 阶段 6：高级空间化

目标：在核心流程可用后，再投入高成本视觉。

候选：
- 圆柱大厅正式 3D / 伪 3D 实现。
- 记忆云视图。
- 坠落 / 回程完整动画。
- 记忆点沉入云中。
- 情绪极坐标漫游。

验收：
- 不牺牲聊天主流程。
- 不牺牲列表、表单、设置的可读性。
- 在低性能设备上有简化版本。

阶段 1 完成后，再进入阶段 2，开始把真实页面和功能逐个映射进去。
