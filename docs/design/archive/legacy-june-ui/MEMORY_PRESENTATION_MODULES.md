# Memory Card Components

本文档定义 Memory Card 中所有可呈现板块的规范。Memory Card = 统一外壳 + 板块组装，AI 根据内容判断装配哪些板块，按骨架规则排列。

## 范式：容器 + 板块组装

不再使用「主模块 6 选 1」的模式。每条记忆的 Memory Summary Card 由一个统一凝露外壳 + 若干板块组装而成。AI 根据内容判断该出现哪些板块，按下文的骨架排版规则放置。

一张卡片可以同时包含多个板块（如「标题 + 数字 + 文字注释 + sparkline + LinkAttachment」），也可以只有一个板块（如纯文字卡）。板块之间不嵌套，是平行原子组件。

## 固定板块 vs 活动板块

每张 Memory Card 分两类板块：

### 固定板块（外壳层 / Fixed Shell）

承担卡片基础结构，不参与「按内容装配」的判断，触发条件满足时自动出现：

- **情绪角晕**（左上角色彩过渡）
- **状态块**（仅异常状态时出现）
- **Foot**（tags + 聊聊按钮）

固定板块在 Memory Card 完整形态下随触发条件出现。

### 活动板块（内容组件 / Modular Boards）

承担具体内容呈现，AI 按记忆内容自由装配：

- 标题
- 文字段落
- Quote
- 引述对象
- 数字
- 表格
- Sparkline / 进度条
- Media
- LinkAttachment

### 聊天召回简化模式

当 Memory Card 被角色在聊天气泡里召回（例如 TA 在对话中引用一条旧记忆）时，卡片以**简化形态**显示：

- **去掉所有固定板块**（情绪角晕、状态块、Foot 全部不显示）
- **只保留活动板块**
- 卡片外壳保留凝露材质和圆角，但更轻、更紧凑
- 没有 tags、聊聊按钮、状态指示

简化形态服务于聊天上下文，用户已经在和 TA 对话，不需要重复操作入口；情绪坐标也不重要（因为离开了云团语境）。

完整形态 vs 简化形态切换规则：

| 出现位置 | 形态 |
|---|---|
| Memory Review 圆柱屏 | 完整形态 |
| 记忆云水珠展开 | 完整形态 |
| 角色聊天气泡内召回 | 简化形态 |
| Full Detail View | 不适用（详情页是另一种 layout，不是 Summary Card） |

## 固定板块规范

### 情绪角晕

卡片左上角色彩过渡，按愉悦度 (V) × 唤起度 (A) 二维映射：

| 象限 | 表达 | 颜色 |
|---|---|---|
| V+ A+ | 兴奋愉悦 | 暖橙红 #E89A8E |
| V+ A− | 平静满足 | 柔粉 #E5C7CB |
| V− A+ | 紧张焦虑 | 紫红 #9E7A8A |
| V− A− | 低落疲惫 | 深蓝灰 #6F7A8A |
| 原点 | 中性 | 浅米 #DCD2CE |
| 低置信 | 不强行定位 | 几乎透明 |

色晕从卡片左上角呈 radial gradient 向外扩散，覆盖约 30-40% 卡片面积，透明度低，不抢主体戏份。**不显示任何文字判语**（不写「情绪 · 中性+」这种）。色点的颜色和水珠在云团里的颜色保持一致。

#### 坐标规则

情绪角晕使用同一套二维坐标：**愉悦度 Valence × 唤起度 Arousal**。这里的「四维」在视觉上落为四个象限，不是四套互相独立的标签。

| 字段 | 含义 | 取值 |
|---|---|---|
| `valence` | 愉悦度；正向 / 负向 | -1.0 ~ 1.0 |
| `arousal` | 唤起度；高能量 / 低能量 | -1.0 ~ 1.0 |
| `confidence` | AI 对这个坐标的把握 | 0.0 ~ 1.0 |
| `evidence` | 支撑坐标的原文片段或来源说明 | 详情页可见 |
| `userOverride` | 用户手动修正后的坐标 | 有修正时覆盖 AI 坐标 |

视觉映射规则：

- **色相由象限决定**：V+ A+ 暖橙红，V+ A− 柔粉，V− A+ 紫红，V− A− 深蓝灰，接近原点时转为浅米中性。
- **强度由离原点距离决定**：越靠近边缘，色晕越明显；越靠近中心，越接近中性。
- **透明度由置信度控制**：低置信时几乎透明，不强行把一条普通事实染成情绪记忆。
- **面积保持克制**：角晕默认覆盖 30-40% 卡面，极强情绪最多扩到 45%，不能压过内容。
- **Summary Card 不显示数值、不显示情绪词**：用户只感受到氛围，不看到「AI 给你判了一个情绪」。

Full Detail View 可以在「AI 理解 / 识别信息」折叠区里展示情绪坐标依据。情绪不设置独立修正控件；所有理解偏差统一通过详情页的「聊聊」或「编辑」处理。用户修正后，后台同步更新相关字段，云团位置和角晕跟随更新。

### 状态块

仅异常状态时出现，位于卡片左上角（在情绪角晕之上的图层）：

- **待确认 / 需复核** → 琥珀色块 + 白文字（背景 rgba(216,160,90,.16) + 边框 rgba(216,160,90,.34) + 文字 #B57A2E）
- **已撤销 / 已取消** → 灰色块 + 文字（背景 rgba(168,144,142,.16) + 文字 #7A6664）

胶囊形态：4px 上下 padding + 9px 左右 padding，圆角 999px，前置 6px 小圆点（同色）。

**正常状态（已确认、进行中、已完成等）不显示状态块**——避免视觉噪音。

### Foot

卡片最底部固定区域，承载分类和入口：

#### Tags

- 沿用系统现有 tags.json，**英文显示**（保持系统一致，避免英中混用）
- **不带 emoji**（即使系统数据里有 emoji icon，Memory Card foot 不显示）
- **不带 hashtag**（# 前缀不加，伴侣 App 语气和社交媒体记号撞）
- 染色文字：暖灰 #8E646C
- 字号 10-11px，letter-spacing 0.10em
- 多个 tag 之间用 10-12px gap，无分隔符
- 系统硬上限 3 个
- 可点击，跳到该 tag 的聚合屏

#### 聊聊按钮

- 中文「聊聊」/ 英文「Discuss」
- 主色填充圆角胶囊（背景 #C08E96，白文字）
- 7px 上下 padding + 13px 左右 padding，letter-spacing 0.10em
- 常驻 Foot 最右侧，不藏不隐
- 点击进入与角色的对话，自动带上当前卡片作为上下文

## 活动板块规范

### 标题 (Title)

#### 适用场景
当卡片有结构化主体（数字、表格、复杂组合）需要短归类时使用。

#### 不适用场景
纯文字卡、Quote 卡、Media 卡通常不带标题——主体本身就是叙述。

#### 视觉规格
- 14px
- ink-mid 色（#6F5A59）
- weight 600
- letter-spacing 0.04em
- 独占一行，紧接状态块下方（或卡片顶部，如果没有状态块）

#### 与水滴短文案的关系

水滴短文案（云团里 2-4 字显示）是运行时生成的氛围/主题/动作词，与标题维度可能重合（睡眠 vs 睡眠）。重复不要紧：

1. 展开动效中水珠短文案随转场被吸收，不与标题同框
2. 即使同框，认知节奏上"先在云上扫到、再在卡片读到"也合理
3. AI 选水珠文案时优先选不同维度（氛围/动作），让自然错开，但不强制

### 文字段落 (Text)

#### 用途
普通事件、事实、情绪、偏好、关系、感受等叙述性内容。**默认板块**——AI 在没有更强结构时回退到这里。

#### 视觉规格
- 14.5px
- line-height 1.78
- 色 rgba(95,75,74,.96)
- letter-spacing 0.01em
- 支持 emphasis 高亮（局部背景色 rgba(227,194,196,.42)）

#### 用例
- 「最近你对周末安排有点抗拒，更想把时间留给自己。」
- 「看完第一部，你最被打动的是那种巨大空旷里的孤独感。」
- 数字卡里的注释（"入睡偏晚，时长比平时少一点"）

### Quote

#### 用途
保留用户原话、阅读摘录、影视台词等原文。原话本身比 AI 改写更重要时使用。

#### 视觉规格（首版最简方案）
- 左侧 2px 细色条（垂直渐变，主色到淡）
- Quote 文本：17px，weight 420，色 #604848，line-height 1.72
- quote-context（可选小字解释）：12px，soft 色

#### 后续美化
首版先用「细色条 + 略大字号」最简方案，后续可补：意大利体倾斜、引号字符装饰、装饰元素。

#### 引述对象绑定
Quote 通常需要标识说话人——见下方「引述对象」板块。

### 引述对象 (SubjectReference)

#### 用途
标识 Quote / 感受文字 所引用的非用户本人的第三方实体。**替代旧设计中的大头像/封面贴片**。

#### 适用条件
- Quote 没有自带说话人，且来自用户已知人物
- 感受文字关于一个具体作品，但作品名不在感受里自然出现
- 引用的实体属于**用户世界里的已知实体**（通讯录人物 / 用户在意的作品）

#### 不适用
- 用户自己的内心独白（默认主语是用户本人）
- 主体内容已经自然交代了引用对象（"今天和朋友 A 吃饭..."）
- **陌生网络发布者**（小红书博主、微博账号、公众号作者、评论区路人）——这些出处由 LinkAttachment 承担

#### 数据形态
- `subjectKind`: `"person"` | `"work"`
- `subjectName`: 实体显示名
- `subjectContext`: 简短上下文（"通话中"、"第一部"、"周五吃饭"）

只覆盖人物 + 作品两类，其他实体（地点、品牌、项目）不开口子。

#### 视觉规格
- 11px
- ink-soft 色 #A8908E
- letter-spacing 0.05em
- 无背景、无边框、无 emoji
- 格式：`名字 · 上下文`（用「·」分隔）
- 位于 Quote / 感受文字上方一行

举例：
```
妈妈 · 通话中
"院子那棵橘子树今年挂得特别多。"
```
```
沙丘 · 第一部
看完第一部，你最被打动的是那种巨大空旷里的孤独感。
```

#### 边缘情况
- **用户特别关注的博主想升级为已知实体**：通过手动入口（在博主名字上长按 → 加入已知人物）。不主推，作为高阶口子。
- **截图评论区，Quote 是某条评论原话**：不开顶部归属，让 Quote 内的 context 行交代（"小红书评论区里一条质疑的声音"）。

### 数字 (Number)

#### 用途
单一关键数值是卡片核心。

#### 字段（板块原子化后）
- `value`：主数值
- `unit`：单位

**仅此两项**。原版 metric-label（"睡眠" 那种小写大字 letter-spaced 标签）已删除——由独立的标题板块承担归类，避免视觉混淆。

#### 视觉规格
- value 42-46px（移动端 36-40px），weight 520，色 #5F4B4A
- unit 13px，soft 色 #A8908E，与 value baseline 对齐
- 左对齐，不居中（靠大字号撑视觉权重）

#### 与文字注释并排规则
当数字 + 文字注释同时出现：

- **优先并排**：数字左 + 文字右，文字从单位右侧开始，多行自然换行
- **过长 fallback**：数字字符数过多（占行宽 > 55-60%）时回退到上下堆叠

```
6.8 小时      入睡偏晚，时长比
              平时少一点
```

或 fallback：
```
¥1,500,000
投资本金回收
```

#### 与其他板块的协同
- sparkline / 进度条：紧接数字组下方
- 表格（拆分细节）：紧接 sparkline/进度条之后
- 数字 + 表格的「头条 + 细节」组合是常见样式

### 表格 (Table)

#### 用途
**任意 label-value 多行结构**。value 类型不限——数字、文字、混合都行。

#### 应用场景（汇总自原 Plan / 支持数值的所有职责）
- **单事件**：时间 / 地点 / 事项（替代原 Plan 板块）
- **订单 / 票据**：商家 / 金额 / 内容
- **诊断报告**：影像 / 结论 / 医嘱 / 随访
- **数字拆分**：TA 30% ¥450 / 你保留 ¥1,050（替代原"支持数值"板块）
- **任务清单（只读）**：☐ 项目 1 / ☑ 项目 2 / ☐ 项目 3

#### 视觉规格
- label 左对齐，窄列（约 60px）
- value 右对齐，宽列
- 行间 hairline 分隔（rgba(117,97,95,.14)）
- 行内 padding 8px 上下
- 单行 13px，line-height 1.4
- 多行 value 换行后仍右对齐

#### 任务状态符号（只读展示）
当 Table 用于任务清单时，状态用文字符号呈现：

- `☐` 待办
- `☑` 已完成
- `⊘` 已取消

**不可点击**——任务管理走日程面的交互界面。Memory Card 只读展示。

#### 与数字板块的边界
- 有头条数字（一个明显比其他大的主数值）→ 数字板块 + Table（细节）
- 字段并列同等重要、无头条 → 只用 Table

### Sparkline 与进度条

两者互斥，根据数据形态选择。**Memory Card 里 sparkline 视觉收敛到这两种**，不做柱状图、饼图、散点、雷达等。

#### 趋势折线 (Trend Sparkline)

##### 用途
连续维度的趋势暗示（睡眠时长、每日步数、消费节奏、习惯连续度）。

##### 视觉规格
- 1.5px 线宽，主色 #C08E96
- 线下方半透明面填充
- 无网格、无坐标轴、无标签
- 当前最新值用一个小圆点高亮
- 22-28px 高，全宽

##### 触发条件
- ≥ 3 个连续数据点
- 趋势方向对理解有帮助

##### 为什么不用柱状图
- 小波动柱状图看不出区别（柱高几乎一样）
- 视觉较重，和凝露材质不协调
- 数据点数量变化时柱状会变粗变细，形态不稳定

#### 进度条 (Progress Bar)

##### 用途
单值 vs 目标的关系（习惯打卡 5/7、月预算剩余 ¥800/¥3000、阅读进度 47%）。

##### 视觉规格
- 6px 高横扁条
- 圆角 999px
- 主色填充至当前进度，剩余浅灰
- 全宽

##### 为什么不用饼图/环形
- 小尺寸下饼图精度低（30%/70% 视觉上几乎一样）
- 占地形状是方形，破坏「扁长板块在数字下方」的骨架一致性

#### Fallback 规则

| 情况 | 选择 |
|---|---|
| ≥ 3 数据点，表达趋势 | 折线 |
| 单值 + 有目标 | 进度条 |
| < 3 数据点 | 不画 |
| 拆分关系 | 不画，用 Table |

#### 完整图表
带坐标轴、多 series、对比的完整图表（TrendChart）**留给 Insight Card**，不进 Memory Card。

### Media

#### 用途
媒体内容是记忆体验主体。首版仅图片，组件名预留给未来音频/视频。

#### 媒体类型
- **首版（v1）**：仅图片，`mediaKind = "image"`
- **预留**：`audio` / `video`，扩展时只加字段不重构

#### 视觉规格

##### 单图
- 全宽，保留原比例
- max-height 180px（超过截顶 letter-box）
- 圆角 18px
- 点击 → 全屏 viewer

##### 多图
- 横向 carousel
- 下方一排小圆点指示器
- 右上角小角标 `1/3` 显示当前 / 总数
- 左右滑动切换

#### Caption
图下方用文字段落板块承担说明，**不开新组件**。

#### 隐私与降级
- 低置信人物识别不直接显示
- 敏感媒体可显示模糊预览或不进 Summary Card
- 加载失败时回退到文字段落

### LinkAttachment

#### 用途
外部链接附件（小红书帖、文章、地点页、商品页、平台原文等）。

#### 数据形态
- `url`：原链接
- `title`：抓取标题或 AI 生成短标题
- `sourceName`：平台名（小红书 / 大众点评 / 公众号 / 等）
- `entityKind`：article / post / place / product / work / profile / webpage / other（可选）

#### 视觉规格
- 扁矩形容器，圆角 14px
- 背景 rgba(255,255,255,.38)，边框 rgba(117,97,95,.10)
- 内部三列：
  - 左：平台色块（24×24，圆角 7px，平台品牌色 + 白色 9px 字号品牌名缩写）
  - 中：标题（12.5px，ink-mid，单行省略号截断）
  - 右：「打开」按钮（暖灰描边胶囊）
- 12px gap，9-10px 内边距

#### 数量
- 单卡可挂 0-N 个
- 多链接并列排，间距 8px
- 超过 3 个时折叠成「共 N 条链接」按钮展开

#### 位置
紧贴 Foot 上方。

#### 平台色参考
- 小红书：#FE2C55
- 大众点评：#F4A91E
- 公众号：#07C160
- 微博：#E6162D
- 其他：取平台官方品牌色或默认主色

## 骨架排版规则

板块的纵向排列分三层约束。

### Tier 1 · 固定位（强约束，不能动）

| 位置 | 板块 | 触发条件 |
|---|---|---|
| 卡片最顶 | 状态块 | 仅异常状态 |
| 紧接状态块下 | 标题 | 仅有时 |
| 卡片最底 | Foot | 永远（简化模式除外）|
| 紧贴 Foot 上方 | LinkAttachment(s) | 仅有时 |

### Tier 2 · 邻近绑定（中约束，必须邻近）

| 绑定关系 | 顺序 | 备注 |
|---|---|---|
| 引述对象 + Quote/感受文字 | 引述对象在上 | 引述对象只对它下面那一块生效 |
| 数字 + 文字注释 | 并排（数字左 文字右） | 过长 fallback 上下堆叠 |
| 数字 + sparkline | sparkline 紧接数字组下方 | 与进度条互斥 |
| 数字 + 进度条 | 进度条紧接数字组下方 | 与 sparkline 互斥 |

### Tier 3 · AI 按内容自由（弱约束）

剩余主体板块（文字 / Quote / 数字 / Table / Media）之间的顺序由 AI 按内容判断，参考原则：

- **视觉重的板块（Media、大数字）通常靠前**——作为「主角」
- **文字段落作为辅助/总结跟在主角后**
- **Quote 作为引证通常在文字后**（除非 Quote 本身是主角，则起头）
- **Table 视情况**——是主体（订单、诊断报告）就靠前，是补充（数字卡的拆分）就靠后

### 装配示例

```
[纯文字关系卡]
文字段落
```

## AI 装配规则

AI 在抽取记忆后按以下顺序处理：

### 1. 触发外壳层固定板块
- 异常状态 → 显示状态块
- 情绪坐标 → 决定角晕颜色（V/A 二维映射）
- tags 从用户 tags.json 中筛选命中项（不自创）
- Foot 总是出现

### 2. 判断需要哪些活动板块
- 有结构化主体（数字 / 多字段）？→ 加标题 + 对应板块
- 有用户原话或摘录需要保留？→ 加 Quote
- Quote / 感受引用了已知人物 / 作品？→ 加引述对象
- 有连续数据 / 目标进度？→ 加 sparkline 或进度条
- 有图片体验主体？→ 加 Media
- 有可打开外部链接？→ 加 LinkAttachment（0-N）

### 3. 排列
- 先放 Tier 1 固定位
- 再处理 Tier 2 邻近绑定
- 剩余按 Tier 3 自由排

### 4. 检查与回退
- 板块加起来超过合理高度？优先保留主体，去除冗余补充
- 任何板块装配失败 → 回退到只用文字段落

## AI 自动评估的克制原则

云团需要 AI 给情绪坐标自动打分，这与「AI 不擅自评分」直觉冲突，但属于产品结构必要。原则上 AI 可以打，但必须克制、透明、可改：

- **默认低置信，弱信号不强行定位**。来源里没有明确情绪表达时坐标置中且低置信，水珠漂浮在云团中央/边缘，不被错误情绪化。
- **永远不把分数显示成对对象的好坏评价**。不在卡片正面出现五星、N 分、AI 评价 = 高这类文字。坐标只作空间元数据，不翻译成判语。
- **不做对象级评分**。不给作品、餐厅、人物自动打分；用户的主观感受走 Text / Quote 由用户自己表达。
- **打分依据必须可看可改**。Full Detail View 展示坐标依据的原文片段；用户不直接改分数，而是通过统一的「聊聊」或「编辑」纠正 AI 理解。
- **AI 不主动赋予其他主观评价**。情绪坐标之外的主观字段（好坏、推荐度、喜爱度）一律留空，由用户表达。

## Memory Card vs Insight Card

这是两个不同物种，不要混淆：

- **Memory Card**：点状记录，单条记忆的呈现。本文档定义的所有板块都是 Memory Card 范畴。Memory Card 有两种深度：Summary Card（瀑布流/水珠展开）和 Full Detail View（完整详情）。Summary 和 Detail 是同一条记忆的不同深度，都属于 Memory Card。
- **Insight Card**：综合分析整理，多条记忆聚合后的洞察。Insight Card 可以使用 Memory Card 不允许的元素：完整图表（带轴、多 series、对比）、跨记忆关联、长时序数据等。

**Memory Card 板块清单不包括**：完整 TrendChart、柱状图、饼图、雷达图、散点图、Timeline 视图、可交互的 Checklist。这些都属于 Insight Card 或专门功能屏（日程面、健康屏等）的职责。
