# 白板 / 桌面工作台视觉规则 v0

> 状态：首页与媒体交互统一使用 Lieflat Palm；不再保留独立墨蓝功能色
> 日期：2026-08-14
> 上位产品决策：`docs/design/whiteboard-requirements.md`
> 页面与数据边界：`docs/design/whiteboard-ui-spine-contract.md`
> 应用级生产 Token：`docs/design/春雨昼眠UI Token.md`、`lib/ui/core/themes/spring_rain_ui_tokens.dart`

## 1. 这份规则解决什么

这份文档固定白板 / 桌面工作台的视觉母语，使首页、卡片库、全屏白板、阅读空间、记忆空间、任务房间和媒体查看器看起来属于同一个产品，同时保留各自的使用目的。

它不是 Kami 模板的复制，也不是新的独立色板。生产实现仍以 `SpringRainUiTokens` 的语义 Token 为准；本文件补充桌面端的面积比例、排版关系、表面差异、交互状态和验收方法。

一句话方向：

> 暖纸承载内容，单一强调色表达行动，文字与留白建立秩序，所有工具都在需要时浮现、完成后退场。

## 2. 参考来源与迁移边界

### 2.1 外部参考

- [tw93/Kami](https://github.com/tw93/Kami)：借鉴暖纸底色、单一强调色、暖灰体系、排版主导层级、克制容器和基于真实渲染的视觉修复流程。
- [Kami SKILL](https://github.com/tw93/Kami/blob/main/SKILL.md) 明确把自身定位为文档 / 静态页面约束，而非动态应用 UI 框架。因此本项目只迁移其视觉原则，不照搬文档模板与生产工作流。
- Kami 仓库使用 MIT License；若以后复制实质代码或模板，必须保留相应版权与许可声明。仓库内第三方字体的可分发权不随 MIT 自动转移，本项目不直接使用 `TsangerJinKai02` 字体文件。
- 首页图表的外部研究和授权边界继续见 `docs/development/WHITEBOARD_EXTERNAL_REFERENCE_AUDIT.md`。

### 2.2 必须保留的 Here I am 身份

- 手机「春雨昼眠」仍是需要对照的气质基线；桌面首页、媒体时间码、跳转和标注创建统一使用 Lieflat Palm 的纸灰、咖色文字和低饱和绿，不再保留 Kami 墨蓝功能色。
- 暖金只属于林埃陪伴、需要注意但不危险的提醒，不升级为第二套装饰色。
- Chat 的雨夜暗色世界继续使用自己的场景 Token；白板规则不得反向覆盖 Chat。
- 桌面与手机共享语义色和内容身份，但可根据屏幕密度调整布局，不要求像素级镜像。

## 3. 十条不可破坏的视觉原则

1. **不用纯白作为大面积底色**：默认使用暖象牙 / 暖纸色；白色只允许出现在局部高亮或媒体本身。
2. **只有一个品牌强调色**：桌面工作面统一使用 Palm 绿，单一画面中的强调色覆盖面积原则上不超过 5%。
3. **所有中性色必须偏暖**：禁止冷蓝灰、Material 默认蓝灰和高对比纯黑白组合。
4. **内容优先于容器**：先用排版、留白和底色差建立层级，再考虑边框与阴影。
5. **一个模块最多使用一种抬升手段**：底色、边框、阴影三者不同时拉满。
6. **标题属于下方内容**：标题下方间距必须明显小于它与上一区块的间距，建议至少形成 1:2 的差异。
7. **控件按需浮现**：全屏白板与沉浸阅读不保留常驻顶栏或永久侧栏。
8. **状态色只表达状态**：成功、警告、失败、授权、等待不能变成装饰性配色。
9. **动效只解释变化**：不为“高级感”添加循环漂浮、弹跳、光晕扫过或大幅位移。
10. **真实渲染才算设计证据**：规则、代码和口头描述都不能替代桌面窗口截图与交互状态检查。

### 4.2 面积比例

- 暖中性色：90–95%。
- 品牌鼠尾草绿：0–5%。
- 单个语义状态色：通常不超过 1–2%。
- 暖金：一屏原则上只出现一个注意焦点；没有林埃语义时不用。

强调色优先出现在线、字、图标、小面积选中底和焦点环上，不用作大卡片整面背景。悬浮球保持中性浅绿 / 象牙材质，只用小状态点表达运行、等待决定或失败。

### 4.3 明暗与渐变

- 普通页面、模块和卡片默认不用渐变。
- 允许渐变的例外：林埃悬浮球的轻微材质高光、媒体播放器上下控制层的透明衰减、需要保持可读性的图片边缘遮罩。
- 不使用纯黑阴影。阴影从 `textPrimary` 派生，保持暖色倾向。
- 深色媒体面必须建立独立 `mediaCanvas` 语义 Token，不能在业务组件里直接写 `#000000`。

### 4.4 当前三套候选配色

三套方案曾使用同一首页结构比较；当前结论是首页与媒体交互采用 Palm，Mono 保留为高密度 / 打印降级，Kami 墨蓝只作为已结束的候选记录，不进入生产组件。最终 Flutter 实现仍需把这些角色映射为生产语义 Token，不在组件内散落裸色值。

#### A. Lieflat Mono

来源：`lieflat-charts/mono-tokens.js`。逻辑是纸灰底、炭黑墨，明度承担数据层级。

| 角色 | 色值 | 用法 |
|---|---:|---|
| `PAPER` | `#F0EFEB` | 页面与普通模块共同底色，模块主要靠留白和发丝线分隔 |
| `INK` | `#1C1C1A` | 主文字、最重要数据、深色侧栏 / 单张暗卡 |
| `MUTED` | `#8F8E88` | 次级说明、时间、坐标标签 |
| `FAINT` | `#C6C5BF` | 来源、辅助刻度、低优先级结构 |
| `GRID` | `#DEDDD6` | 网格线、分隔线、卡片边界 |
| `LADDER` | `#1C1C1A / #4A4944 / #6A6963 / #8F8E88 / #B0AFA9 / #C6C5BF / #D8D7D1` | 多级数据从重要到次要依次分配，不引入色相 |
| `DARK` | 底 `#1C1C1A`，字 `#F0EFEB`，网格 `#2E2D29` | 侧栏或最多一张重点数据面，不把整页做成深色 |

#### B. Lieflat Palm

来源：`lieflat-charts/color-presets.js` 的 `PALM`。逻辑是暖灰纸底、咖色文字、低饱和绿承载数据，琥珀只标一个重点。

| 角色 | 色值 | 用法 |
|---|---:|---|
| `BG` | `#F0EFEB` | 页面与普通模块底色；与 Mono 共用纸灰基底 |
| `TXT` | `#58402E` | 标题、正文和数字；绿色不代替正文色 |
| `MUT / GRID` | `rgba(88,64,46,.60)` / `rgba(88,64,46,.16)` | 次级文字与发丝结构 |
| `DATA` | `#43593B` | 主数据、活动项、睡眠区间 |
| `BEAD` | `#77835A` | 点阵、次级数据、连接结构 |
| `FAINTDATA` | `#ACAD79` | 低值、安静数据、深色侧栏次级字 |
| `HERO` | `#D4A017` | 一张图里的唯一峰值 / 当前选择，不作为普通装饰 |
| `HERODK` | `#F2D17E` | 深绿底上的重点数据 |
| `RAMP` | `#F2D17E / #ACAD79 / #929960 / #77835A / #43593B` | 仅用于有序数值，颜色由浅到深对应强度 |
| `DARK` | `#28311F` | 侧栏或单张暗卡；其余大面积仍为纸灰 |

Palm 的分类色最多稳定承载四类；琥珀和橄榄语义不同，不能当作两个平等类目平均使用。

#### C. Kami 墨蓝

来源：`kami/styles.css`。保留 Kami 自身的暖纸与墨蓝，不采用 Lieflat 的 Porcelain 蓝阶。

| 角色 | 色值 | 用法 |
|---|---:|---|
| `PARCHMENT / IVORY` | `#F5F4ED / #FAF9F5` | 页面底与轻抬升模块 |
| `WARM_SAND` | `#E8E6DC` | 分隔线、输入边界、安静承载 |
| `NEAR_BLACK` | `#141413` | 主标题和正文 |
| `OLIVE / STONE` | `#504E49 / #6B6A64` | 次级正文与元信息 |
| `BRAND` | `#1B365D` | 侧栏、主数据、活动导航 |
| `BRAND_LIGHT` | `#2D5A8A` | 次级数据和少量交互反馈 |
| `BLUE_TINTS` | `#D6E1EE / #E4ECF5 / #EEF2F7` | 选中底、低值数据和柔和状态，不做大面积彩色卡 |
| `BORDER_SOFT` | `#E5E3D8` | 轻边界 |

Lieflat Mono / Palm 的 `#F0EFEB` 与 Kami 的 `#F5F4ED`、`#FAF9F5` 属于同一类低饱和暖灰纸色。Kami 更亮、更偏象牙；Lieflat 更灰、更接近未漂白纸。因此两者气质相近，可以共享布局和材质规则，但不能把色值视为完全相同。

## 5. 字体与信息层级

### 5.1 字体分工

- **所有中文**：汇文明朝体，覆盖导航、按钮、表单、卡片、字幕、正文与状态。参考字体资产为 CC0 1.0；生产前必须对子集、包体积、缺字和标点宽度做真机检查。
- **所有英文、数字、路径、时间码与代码**：Cascadia Code，使用 Microsoft 官方发行资产与许可。
- **混排与回退**：拉丁字符优先 Cascadia Code，CJK 字符进入汇文明朝体；中文回退系统宋体 / 明朝体，英文回退系统等宽字体。

### 5.2 桌面字号阶梯

字号只能从既定阶梯选择，禁止为单个组件发明 13.5 / 14.5 / 17.5 等近邻值。

| 层级 | 建议值 | 行高 | 用途 |
|---|---:|---:|---|
| Display | 28–32px | 1.15–1.25 | 空间标题、重要空状态 |
| 页面标题 | 24px | 1.28 | 首页、卡片库、任务房间 |
| 大分区标题 | 18px | 1.35 | 页面内真正独立的大分区；不用于每张首页模块 |
| 模块标题 | 15px | 1.35 | 高密度首页模块，使用主文字色与 600 字重 |
| 内容标题 | 14px | 1.4 | 卡片、任务、阅读条目 |
| 正文 | 14px | 1.5–1.65 | 说明、摘要、对话 |
| 元信息 | 12px | 1.4–1.5 | 时间、来源、范围、计数；默认无填色底 |
| 状态标签 | 11px | 1.35 | 优先级与持续状态；不得承载时间归属或连续正文 |

- 中文屏幕阅读正文默认行高 1.65–1.75，可由用户调节。
- 标题字重以 500 / 600 为主；不用 800 / 900 制造层级。
- 数字图表和时间列使用 lining + tabular numbers，保证基线和列宽稳定。
- 斜体只承载原文语义或林埃的特殊动作语气，不作为普遍装饰。

## 6. 间距、圆角与尺寸

### 6.1 间距

只使用现有序列：`2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32 / 40`。

常用关系：

- 图标与文字：6–8px。
- 卡片内部：12–16px；大型模块：16–20px。
- 同组条目：8–12px。
- 标题到内容：8–12px。
- 区块到区块：20–32px。
- 桌面窗口安全边距：20–32px；全屏白板例外，由悬浮工具自身留边。

### 6.2 圆角

收紧为 `6 / 10 / 14 / 18 / pill`，不再把 24–28px 大圆角作为常规工作台语言：

- 6px：复选框、小状态块。
- 10px：首页模块、工具按钮、小菜单项、白板卡片。
- 14px：输入框、筛选器、普通浮层和聊天承载面。
- 18px：只留给需要明显脱离工作面的模态层；同一首页不反复使用。
- pill：Chip、状态与极短筛选；禁止把普通按钮全部胶囊化。

同一层级中圆角不混用；一屏最多出现三个非 pill 圆角等级。

### 6.3 控件

- 控件高度只使用 36 / 44 / 52px。
- 图标只使用 16 / 20 / 24px；林埃悬浮球和内容封面不属于普通图标。
- 点击目标不得小于 36×36px；关键操作目标优先 44×44px。

## 7. 容器、边框与阴影

### 7.1 普通模块

- 默认：`surface` 填充 + 无阴影。
- 需要与画布分离：`surfaceRaised` + `shadowLow`。
- 需要可编辑边界：1px `divider` / `outline`，不再额外加明显阴影。
- 需要强调：使用一条 1–2px accent 边、焦点环或标题颜色，不把整张卡染绿。

禁止“明显底色 + 完整描边 + 深阴影 + 大圆角”四件套。卡片嵌套最多一层；第二层优先改为分隔线、缩进或排版组。

### 7.2 阴影

- `shadowLow`：菜单、轻浮层、可拖动面板。
- `shadowMedium`：对话窗、任务中心、模态层。
- 普通列表行、图表、筛选器、白板内容卡不加阴影。
- Hover 抬升最多 1px；密集网格可只变底色或边界，不移动布局。

### 7.3 玻璃

玻璃只用于覆盖在画布或图片上的临时工具，不作为所有卡片的默认材质：

- 允许：悬浮导航、林埃对话、画布工具、媒体控制条。
- 纯色 / 纸张皮肤禁止滥用玻璃。底图皮肤可以让一级首页模块共享同一磨砂材质，但卡片内部不得继续嵌套 blur；文字与图表必须通过实色或受控透明度达到可读对比，不能靠阴影补救。
- 打开覆盖面板时，背景可以轻微降对比，但非模态面板不使用全屏 scrim。

## 8. 各工作面的差异化规则

### 8.1 首页 / 模块化工作台

- 在一个常见桌面窗口高度内读懂主要状态，不依赖长页面滚动。
- 桌面侧栏采用「短横线 + 文字」的低噪声导航，不以图标墙或第二条顶栏重复表达页面层级；活动项背后用左深右浅、边缘不规则的淡绿水墨笔触，不用左侧实线；侧栏可以按工作面整体收起。
- 首页展开侧栏宽度以 144–148px 为上限，使用与页面相同的纸灰底；不使用贯穿全高的实线或深绿整面填充，只允许一段上下渐隐的浅纸缝阴影。收起后内容区必须真正回收为 0px，只保留 32–36px 的打开把手；进入全屏白板、阅读或视频研读时默认收起。
- 侧栏收起时分隔线、活动水墨、导航文字和内部留白必须一起消失；打开把手悬浮在主内容一侧，不压住旧边界，也不露出一条绿色残影。
- 模块网格允许不同尺寸，但使用同一边线、标题基线和间距节奏。
- 首屏保持 8–12 个有真实内容或明确演示标记的紧凑模块；空模块不为凑布局而存在。
- 每个模块必须至少提供一个可执行去向；没有后续行为的数据不伪装成按钮。
- 图表标题先说结论，再显示数据；不以“本周数据”“阅读统计”这类类别词充当洞察。

### 8.2 全屏白板

- 画布占满窗口；无常驻顶栏、Tab 条或聊天侧栏。
- 背景点阵使用暖灰低对比圆点；100% 缩放时建议 20–24px 间距、约 1px 点径。缩放过小时降低或关闭点阵，避免摩尔纹。
- 内容卡默认使用 `surfaceRaised`，边界轻于选择态；选中时使用 accent 边 + soft focus ring。
- 分组框只描述范围，不做厚重容器；其填充比画布只高一个明度层级。
- 连线默认暖灰或低浓度鼠尾草绿，1–1.5px；未选中时不长期显示大段标签。
- 导航、卡片库、工具和林埃对话关闭后必须完全退场，不留下兜底栏。

### 8.3 卡片库

- 高密度优先，卡片之间依靠对齐与稳定尺寸形成秩序。
- 卡片首先是内容预览，不是类型字段表。媒体卡让图片、视频、网页或书封占 60–72% 的高度，并从卡片内容区顶端贴边开始，不留下默认按钮内距形成的纸色窄条；标题、来源、标签和时间退到最多两行的附属区。纯文字卡直接预览正文，不造封面、不把正文压成窄条。
- 筛选器使用 soft / muted 面，不使用一排高饱和胶囊。
- Hover 表示“可打开 / 可拖动”，Selected 表示“已加入批量操作”；两者视觉不同。
- 图片、书籍、网页、视频等可以有不同预览，但卡片外壳和元信息节奏一致。

### 8.4 阅读空间 / 记忆空间

- 这是纸张感最强的表面，但仍不是一张长网页外壳。
- 正文阅读列建议 680–760px；中文每行约 30–40 字，避免铺满超宽屏。
- 目录、批注、来源证据和林埃对话按需悬浮；默认让内容占据视觉中心。
- 记忆证据与修订记录使用结构化次级面，不与正文争夺主层级。
- 漫画保持原图颜色，纸张色只作为页间留白；不得在图像上覆盖暖黄滤镜。
- 阅读位置、批注锚点和当前选择必须可辨认，但不使用大面积高亮。

### 8.5 视频 / 图片 / 媒体查看器

- 媒体本身是主角，允许使用独立深色 `mediaCanvas`。
- 品牌绿只用于播放进度、焦点和关键操作；控制条不做彩色装饰。
- 控件闲置后淡出，鼠标移动、键盘操作或触摸后恢复。
- 视频消费视图默认同时呈现播放器、可拖动时间轴与带时间码字幕；点击字幕跳转画面，播放时反向高亮当前字幕，不把它们藏进二级弹窗。
- 桌面视频研读默认采用左右双面：左侧直接承载平台允许的嵌入播放器，右侧承载字幕 / 时间线与标注卡。右侧是可折叠的工作面辅助坞，不是全局永久侧栏；用户可切到底部停靠，窄屏自动下移。全局导航默认退场，不在播放器上方再叠工作台顶栏。
- 视频是默认主表面：左右停靠初始比例约 65:35，上下停靠约 70:30；两种方向都提供可拖动分隔器，并设置播放器与字幕区的最小宽高，不能让字幕面反客为主。
- 右侧时间码使用 Palm 深绿；点击时间码跳转播放器。每个时间段旁提供一个同色小方块，点击后在原字幕项下插入视频标注卡，保存时同时写入稳定时间 Anchor 与 Annotation Card。
- 字幕来源（平台 / 创作者 / 用户导入 / 本机转写）和可用状态必须可见；缺字幕时明确显示“需要字幕”，不生成演示性假字幕。
- 时间锚点与区间锚点显示在同一条时间轴上；建立锚点后给出短暂确认，并允许从白板卡片、批注或任务产物跳回精确画面。
- 字幕、时间锚点、批注气泡必须保持足够对比，并避开内容关键区域。
- 从媒体返回白板时恢复原 viewport、选择与来源位置。

### 8.6 林埃悬浮对话与任务房间

- 悬浮球是入口与状态锚点，不是品牌广告位；主体颜色保持中性，状态用小点或环表达。
- 展开对话保留轻量承载面，消息可有浮动感，但不追求完全无衬底而牺牲任务状态和可读性。
- 用户消息用浅 Palm 绿半透明气泡与深色文字；发送按钮使用几何居中的纸飞机图标。悬浮对话输入框的 Focus 使用低浓度 Palm 绿边界与柔和焦点环，禁止琥珀 / 橘色描边。
- 关系主对话使用较轻容器；任务房间可以更结构化，因为需要承载时间线、授权、产物和记忆结晶。
- 后台任务不持续占据主对话；等待决定、失败和完成摘要通过任务条 / 任务中心进入。任务中心使用紧凑多列、分段进度和真实分布图，1440×900 内至少同时呈现 8–12 条摘要，不放大成稀疏文字表格。

## 9. 图表规则

- 一个图只回答一个问题；标题直接陈述发现或变化。
- 本地 Lieflat Charts 参考已同步至 v1.2.0（`1547bb3`）。图形目录仍包含 49 种类型，新增的 12 组双语报告模板主要用于研究首页信息密度与叙事编排。
- 睡眠 G1 Range Capsules、运动 F10 Dot Heat、账本 F9 Rung Waterfall、阅读 L3 Barcode Lollipop 是首批合适映射，不是固定白名单。新增数据模块先从 Lupi Editorial 与 Basics 中各找候选，再按需看 Glance；至少比较 3 个几何方案，按数据语义和一眼可读性选择，不为形式丰富而随机换图。
- 组件展板与跨模块图表目录要主动覆盖更多适配真实数据的图形语法，例如 range、dot heat、waterfall、lollipop、waffle、stream、rungs 和 treemap；多样性发生在整个产品体系，而不是把多张无关图塞进同一个首页模块。
- 同一图表只使用一个品牌强调色；其余序列使用暖灰阶。只有真实语义状态才引入状态色。
- Palm 的琥珀金 `#D4A017` 必须在合适的峰值、当前焦点或异常节点中真实出现，但同一视图通常只出现一个，不作为第二品牌色平均铺开。
- 坐标轴、网格线和标签低对比；数据本体与结论最高对比。
- 不使用 3D、发光、玻璃柱、彩虹色板、装饰性渐变或无意义面积图。
- 份额不超过 6 类时才考虑 donut；更多类别改用横向条形。
- 单一时间序列若重点是绝对数量变化，优先柱状；若重点是连续趋势或变化率，才使用折线。
- 首页不放复杂关系网络；关系图进入相应白板或详细观察面。
- 图表必须具备空数据、数据不足、加载、失败和最后更新时间状态。

## 10. 动效与交互反馈

沿用现有三档时间：

- 120ms：Hover、Pressed、焦点、图标反馈。
- 220ms：菜单、浮层、筛选和局部切换。
- 360ms：任务房间、阅读视图、较大面板的进入与退出。

规则：

- 位移通常不超过 4–8px。
- 不用弹性回弹作为默认曲线。
- 面板关闭时回到触发锚点附近，帮助理解空间关系。
- 拖拽中的卡片保持原尺寸；用轮廓、透明度和落点预览反馈，不突然放大。
- 支持系统“减少动态效果”；启用后移除位移与缩放，仅保留必要淡入淡出。
- Streaming、后台运行和上传状态不通过无限旋转占据注意力；优先使用进度、阶段文字和安静的状态点。

## 11. 必须覆盖的组件状态

每个可交互组件至少设计并验证：

1. Default
2. Hover
3. Focus-visible
4. Pressed
5. Selected / active（如适用）
6. Disabled
7. Loading / running（如适用）
8. Empty / unavailable（内容组件）
9. Error / needs-decision（任务组件）

状态不能只靠颜色区分；重要状态同时使用文字、图标、形状或位置。键盘焦点必须比 Hover 更明确，并且不能被 `outline: none` 静默删除。

## 12. 视觉验收矩阵

### 12.1 固定视口

桌面 UI 至少检查：

- 1440×900：主力桌面窗口。
- 1280×720：紧凑横屏，验证首页不会退化成长页。
- 1024×768：窄桌面 / 平板横屏，验证模块折叠与覆盖面板。
- 375px 宽：仅检查明确跨端复用的页面；白板本体不要求压缩成手机版画布。

### 12.2 每次交付必须看什么

- 首页：默认、模块重排、数据不足、后台任务等待决定。
- 白板：空画布、普通卡片、选中、多选、打开导航、打开林埃、打开任务中心。
- 卡片库：全部、筛选、搜索无结果、批量选择、拖入白板。
- 阅读器：正文、漫画、批注、目录、沉浸、返回原位置。
- 媒体：播放、暂停、拖动跳转、字幕点击跳转、播放反向高亮、点 / 区间锚点、字幕缺失、失败、返回原位置。
- 任务房间：运行中、授权请求、多产物、完成、结晶选择。

### 12.3 视觉修复协议

用户说“太挤、太空、太重、不好看”时：

1. 先指出具体表面、视口、组件和缺陷类别；
2. 锁定允许修改的目标与必须保留的相邻区域；
3. 做最小的间距、字体、明暗、裁切或 Token 修复；
4. 重新检查目标视口、相邻状态和被共享 Token 影响的页面；
5. 同一元素连续两轮仍未收敛时，不再盲调数值，输出 A / B / C 同框比较供用户选择。

## 13. 禁止模式

- 双顶栏、常驻聊天侧栏、永不消失的页面 Tab 条。
- 一屏大量彩色卡片、每类内容一种主题色。
- 为了“现代感”加入冷蓝灰、霓虹、紫蓝渐变或玻璃泛滥。
- 首页只有三张稀疏大卡，或依靠长滚动才看懂工作台。
- 所有内容都包成圆角卡片，卡片里继续套卡片。
- 用左侧或右侧实心竖线表达 Card、Tab、导航或标注的活动 / 选中状态；底部短横线、完整边框和图表数据线除外。
- 用 emoji / 装饰图标代替真正的信息层级。
- 为填满模块虚构统计数据、任务状态或林埃判断。
- 用缩小字体解决内容过多；应先重写、折叠、合并或改变模块职责。
- 在阅读器上保留工作台导航壳，在白板上保留阅读器工具壳。
- 直接复制 Kami / lieflat 的模板代码、商业字体或非商业授权资源进入生产实现。

## 14. MVP 视觉完成定义

白板 MVP 的视觉可以进入实现，当且仅当：

- 首页、卡片库、白板、阅读空间、媒体查看器、林埃悬浮对话和任务房间都使用同一语义 Token；
- 三类核心表面（工作台 / 画布 / 消费视图）一眼可辨，但不存在三套互不相干的皮肤；
- 画布真正全屏，所有临时工具都能完整退场；
- 首页在 1280×720 内仍能完成主要浏览；
- 关键组件状态与键盘焦点完整；
- 1440×900、1280×720、1024×768 截图完成视觉检查；
- 没有未经标注的假数据、无行为装饰按钮或授权不清的外部资源。
