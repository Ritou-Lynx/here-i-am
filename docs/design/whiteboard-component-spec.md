# 白板 / 桌面工作台组件规范 v0.2

> 状态：基础层经桌面 MVP 真实页面校正；业务组件随真实流程增量完善
> 日期：2026-08-14
> 视觉母语：Lieflat Mono 灰纸基底 + Palm 数据与动作强调
> 上位文档：`whiteboard-requirements.md`、`whiteboard-ui-spine-contract.md`、`whiteboard-visual-rules.md`

## 1. 设计与功能如何并行

组件规范不需要等所有功能想清楚后再开始，也不能脱离功能一次性封死。采用三层并行法：

1. **基础层先冻结**：颜色角色、字体分工、字号阶梯、间距、圆角、控件高度、边界、焦点与禁用规则。除非真实页面暴露系统性问题，否则不因单页偏好修改。
2. **通用组件先形成版本化基线**：按钮、图标按钮、输入框、选择器、菜单、浮层、状态提示、导航行。功能页只能组合它们，不自行发明外观。
3. **业务组件跟功能一起生长**：内容卡、白板节点、字幕行、时间锚点、任务条、记忆确认项、林埃悬浮对话。每明确一条真实流程，就补齐该组件的结构、状态和数据边界。

因此顺序不是“先组件、后功能”，而是：

> 冻结基础规则 → 设计一个真实流程 → 补齐所需业务组件 → 放回页面验证 → 再进入下一条流程。

当前不锁定首页模块的具体排列，也不为尚未确认的 coding 房间细节建立正式组件。

## 2. 组件准入规则

一个新组件进入规范前必须满足：

- 至少被两个页面复用，或承担一个不可替代的产品语义；
- 有明确的默认、交互、等待、空、失败、禁用状态；
- 说明它接收什么数据、触发什么动作、完成后留下什么；
- 在 320px 与常见桌面宽度下不依赖文字截断才能成立；
- 不用额外文案、装饰色、阴影或大圆角填补空白；
- 能回答“为什么它不能由现有组件组合出来”。

一次性页面排版不是组件；图表的几何模板不是按钮或卡片；功能名也不自动等于组件名。

## 3. 基础 Token

### 3.1 桌面工作台颜色角色

业务实现只读取语义角色，不复制裸色值。

| 语义角色 | Palm 参考值 | 用途 |
|---|---:|---|
| `workspaceCanvas` | `#F0EFEB` | 首页、侧栏、卡片库与普通工作面共同底色 |
| `workspaceText` | `#34332F` | 页面标题、模块标题、正文、数字；以中性墨色建立层级 |
| `workspaceTextMuted` | `#74726C` | 时间、来源、次级说明 |
| `workspaceTextFaint` | `#999790` | 极弱辅助信息，不承载功能状态 |
| `workspaceDivider` | `rgba(52,51,47,.13)` | 发丝线、输入边界、分区 |
| `workspaceSurface` | `rgba(255,255,255,.28)` | 模块和普通卡片；只比纸灰亮一个层级，不混入绿色 |
| `workspaceAction` | `#43593B` | 主动作、活动项、主数据 |
| `workspaceActionSecondary` | `#77835A` | 次级数据、轻交互 |
| `workspaceActionSoft` | `#ACAD79` | 低值数据、安静选中底 |
| `workspaceFocus` | `#D4A017` | 单一峰值或当前焦点，不做普通 CTA |
| `workspaceDark` | `#28311F` | 单张暗面或媒体外壳；禁止扩展成整页侧栏 |

媒体时间码、跳转与锚点创建也复用 `workspaceAction / workspaceActionSecondary / workspaceActionSoft`，不再引入独立蓝色。颜色面积纪律：中性灰纸与墨色 90–95%，Palm 绿不超过 5%，琥珀同屏通常只有一个焦点。普通模块、类型标签、时间、来源、筛选基线和图表低值全部先使用灰阶；不得把浅绿混入页面环境底、普通承载和无状态元信息。

### 3.2 字体

- **所有中文**：汇文明朝体，覆盖导航、按钮、表单、卡片、字幕、正文与状态。当前参考仓库字体文件采用 CC0 1.0，但体积约 24.9 MB；进入生产包前必须做字符集子集化与真机缺字检查。
- **所有英文、数字、时间码与代码**：Cascadia Code；生产落地使用 Microsoft 官方发行资产并保留对应许可，不从未知字体站下载。
- **回退顺序**：中文回退到系统宋体 / 明朝体，英文与代码回退到系统等宽字体。不得因某个平台缺字体而回到 Inter 或默认 Material 字体。
- 混排由字符覆盖范围自动分工：拉丁字符优先 Cascadia Code，CJK 字符进入汇文明朝体。

高密度桌面页固定使用：页面标题 24、模块标题 15、内容标题 14、正文 14、元信息 12、短状态 11。18px 只留给页面内部真正独立的大分区，不用于首页每一张模块。组件不得自行创造邻近字号。

### 3.3 几何与密度

- 间距：`2 / 4 / 6 / 8 / 12 / 16 / 20 / 24 / 32 / 40`。
- 圆角：小状态 6；常规组件与卡片 10；输入与普通浮层 14；模态层最多 18；pill 只用于短状态和筛选。
- 控件高度：紧凑 36；默认 44；强调 / 触屏 52。
- 图标：16 / 20 / 24；点击目标不得小于 36×36。
- 发丝线默认 1px；普通组件不用阴影，浮层才使用轻阴影。
- 默认密度为**紧凑、低圆角、高信息量**；页面不通过放大卡片制造层级。

## 4. 通用组件

### 4.1 按钮

| 类型 | 使用场景 | 外观 |
|---|---|---|
| Primary | 每个动作组唯一主动作 | Palm 深绿实底，暖纸文字 |
| Secondary | 次要确认、替代路径 | 透明 / 纸面，1px 暖灰边界 |
| Ghost | 行内低优先级动作 | 无常驻容器，hover 出现浅底 |
| Icon | 播放、折叠、关闭、更多 | 36 或 44 方形目标，图标居中 |
| Destructive | 删除、断开、不可逆操作 | 仅在危险动作出现，不复用品牌绿 |

规则：按钮用动词；一组最多一个 Primary；普通按钮不用 pill；加载时保持原宽度并禁止重复提交；禁用不是降低到不可读。导航、返回、展开和翻页统一使用成套 chevron 图标，不使用 `← / → / ↑` 这类文本箭头。

“更多”是标准省略号图标按钮，必须带可访问名称，不使用裸文字“更多”冒充无框按钮。

低信息量进度（如“处理中”）使用与 Selected 相同的浅绿底、深绿文字和小型旋转指示，不使用深绿实底；深绿 Primary 只保留给可以主动点击的主动作。

### 4.2 输入与选择

- 输入框默认 44px 高，正文输入与聊天可扩展；边界 1px、圆角 14。
- 焦点同时使用边界变化与焦点环，不只靠颜色。
- 普通输入与悬浮对话输入统一使用低浓度 Palm 绿焦点环，不使用琥珀 / 橘色边框。
- 错误文案紧跟字段，说明如何修正；不使用只写“失败”的 toast 替代字段错误。
- 组件展板默认展示有效输入，不为了说明错误状态而常驻一条红色报错；Error 只在真实校验失败时出现，并必须引用已经登记的语义状态色。
- 筛选优先使用紧凑分段、菜单或行内选择；类型多时不铺满一排胶囊。
- 搜索属于卡片库等具体空间，不建立全局常驻顶栏。

### 4.3 菜单、Popover、Dialog

- Menu：短命令列表，不承载复杂设置。
- Popover：与触发点有明确空间关系的轻编辑、预览、筛选。
- Dialog：需要中断当前流程的确认或授权；普通详情不用模态框。
- 非模态浮层关闭后必须完整退场，不保留兜底矩形。
- 授权请求必须显示任务、执行工具、权限对象、风险和允许范围。

### 4.4 侧栏导航行

- 结构固定为“短横线 + 文字”。活动态在文字背后铺一笔不规则淡绿水墨：左侧浓、向右自然淡出，允许轻微毛边；同时加深文字与横线，但不出现左侧实心竖线。
- 展开宽度 144–148px；关闭后内容宽度为 0，只留 32–36px 把手。
- 关闭态必须同时移除侧栏分隔线、活动水墨、内容残影和内部 padding；打开把手完整落在主内容一侧，不骑在旧边界线上。
- 首页可以展开；白板、阅读、视频默认关闭。
- 侧栏与页面共享 `workspaceCanvas`，展开时也不使用贯穿全高的实线；依靠留白与 12–18px、上下渐隐的纸张接缝阴影划分。收起时接缝一并消失。

所有 Card、Tab、导航和状态项都禁止以左侧或右侧实心竖线表达活动、选中或提示。顶层 Tab 位于底部的短横线可以保留，因为它表达基线与轻微抬升；完整卡片边框和图表内部的数据线不受此禁令影响。

### 4.5 标题、元信息、状态与林埃提示

- 页面标题和模块标题都使用 `workspaceText`；模块标题是该模块最先被识别的文字，不得比正文更小、更淡。
- 时间、范围、来源、计数属于元信息，使用 12px `workspaceTextMuted`，默认不装进有底色的 badge。
- “今天”是时间归属，“紧急”是优先级，两者不得共用同级状态标签；时间放在分组标题或元信息，紧急使用 `warning` 语义状态。
- Badge 只表达持续状态或优先级，例如紧急、等待决定、失败、已选择；卡片类型默认使用中性灰标签，不占用 Palm 绿。
- “i 的观察 / 林埃建议”使用正式品牌符号 + 说明文字形成独立签名行，不使用与状态 badge 相同的填色胶囊，也不靠诗性文案制造强调。
- 页面同屏只能有一套明确阅读顺序：页面标题 → 模块标题 → 内容标题 / 关键数据 → 正文 → 元信息。颜色不能倒置这套顺序。

## 5. 产品组件

### 5.1 内容卡 `ContentCard`

统一的是数据身份、边界与操作状态，不是把所有类型压成同一种横条。卡片首先是一张**内容预览**：

- 图片、视频、网页、书封等媒体卡由媒体占据约 60–72% 的可见高度，标题、来源、时间与标签压缩为底部最多两行；
- 媒体预览从卡片内容区最顶端开始，不在媒体与上边界之间留下内边距、默认按钮留白或一条无意义的纸色窄条；
- 纯文字卡直接让正文预览成为主体，在自然段落边界截断；不得虚构封面，也不得把正文压成窄条；
- 标签只作微型附属信息，不与标题、正文争夺视觉面积；
- 不同类型允许不同纵横比，但共用选中、拖动、批量操作与打开逻辑。

卡片库中的“放入白板”是目标选择动作：默认打开 `BoardTargetPicker`，提供最近白板、全部白板搜索和“新建白板”；位于某张白板上下文时，主动作可以改为“放入当前白板”，另提供切换目标。选择后只新增 `BoardItem`，不复制 Card；同一 Card 可以进入多个白板。尚未实现选择器的临时 MVP 必须明确标注实际目标，例如“放入最近白板”，不能用含糊文案伪装成已完成流程。

支持文本、书籍、图片、网页、视频、批注。Hover 表示可打开或拖动；Selected 表示进入批量操作，两者不能共用同一视觉状态。

### 5.2 白板节点 `BoardItem`

- 内容身份来自 Card / Source，不复制一份独立正文。
- 默认低边界；选中为 Palm 绿边 + 轻焦点环；拖动时只抬升 1px。
- 节点工具在选中或 hover 时出现；取消选择后退场。
- 分组和连线是独立对象，不嵌进节点卡外壳。

### 5.3 图表模块 `ChartModule`

固定结构：结论型标题、必要数值、图形、单位 / 时间范围、一个明确去向。图表本身不套第二张卡。

Lieflat Charts 当前本地参考已同步到 v1.2.0（`1547bb3`）：图表目录仍有 49 种图形，更新主要增加 12 组双语报告模板。睡眠 G1、运动 F10、账本 F9、阅读 L3 只是首批示例，不是白名单。每个数据问题先在 Lupi Editorial、Basics 中各比较合适图形，再按需看 Glance；至少提出 3 个候选后按数据语义、可读速度与空间成本选一个。报告模板只用于研究首页密度和叙事层级，不复制受限模板代码。颜色用于数据强度，不把整个模块染绿，也不为“丰富”而随机换图形。

组件展板应持续维护一组真实数据形态的图形样例，例如区间胶囊、点阵热力、瀑布、棒棒糖、waffle、stream、rungs、treemap 等，让整个产品在不同模块中充分利用图表语法；但单个首页模块仍只选择最匹配该问题的一种图形，不把所有类型堆进同一张卡。

### 5.4 字幕行 `TranscriptCue`

结构：`时间码 → 字幕正文 → 绿色方块`。

- 点击时间码：播放器跳转；
- 播放经过：当前行使用 `workspaceActionSoft`，时间码保持 Palm 深绿；
- 点击绿色方块：在原行下方插入 `VideoAnnotationCard`；
- 键盘必须能聚焦时间码和创建按钮；
- 没有可靠时间码时不伪装成可跳转字幕。

### 5.5 视频标注卡 `VideoAnnotationCard`

创建态包含平台、稳定时间 Anchor、输入区、取消与“保存为卡片”。保存态显示正文、时间、来源和返回播放器动作。它是卡片库中的批注卡，不是播放器私有便签。外壳使用普通纸面和完整边框，不使用左侧实心竖线。

### 5.6 后台任务条 `TaskStrip`

只显示任务名、当前阶段、状态、需要用户处理的数量与一个去向。进度细节、授权记录、执行日志和产物留在任务房间，不倒灌主聊天。

状态：排队、运行、等待决定、完成、失败、已取消。只有“等待决定”和“失败”需要显著提醒；普通运行不持续闪烁。

### 5.7 任务中心 `TaskCenter`

> 未纳入当前 Desktop 首页或一级导航；本节仅保留为后续独立 Desktop 方案的研究草案。

任务中心不是放大的文字列表。桌面默认采用运行中 / 等待决定 / 最近完成三列紧凑任务卡，并配一个窄数据栏呈现真实的任务类型、进度刻度与记忆待确认量；在 1440×900 中应能同时看见至少 8–12 个任务摘要。任务卡优先使用工具标记、分段进度、状态点和数量图形，正文只保留任务名、当前阶段与时间。完整日志、授权正文和产物版本仍进入任务房间。

当前三列只是一种任务看板结构草案，不冻结列名、字段或统计模块；等真实任务、授权、产物和记忆确认流程跑通后，再决定哪些列长期存在。

### 5.8 记忆确认项 `MemoryReviewItem`

固定展示候选内容、来源、建议记忆域、压缩后文本和“保留 / 修改 / 不进入记忆”。任务房间材料只有经用户选择和压缩后，才能与 `task_id` 一起成为任务结晶。

### 5.9 工作面辅助坞 `ContextDock`

- 它是当前工作面的可停靠辅助面，不是全局永久右侧栏；桌面宽度通常为 320–380px，可折叠。
- 视频字幕 / 标注、阅读目录 / 批注、卡片详情 / 筛选都可复用同一壳，但内容状态互不串联。
- 视频研读默认停靠右侧；窄屏、专注逐行阅读或用户主动切换时可移到底部。
- 切换停靠方向必须立即改变真实布局并显示当前位置，不得只切按钮样式；在组件展板宽度下也必须能看见右侧与底部的差异。
- 视频始终是主内容：右侧停靠默认约 65:35，底部停靠默认约 70:30。桌面实现提供可拖动 splitter；左右布局调整宽度，上下布局调整高度，并为播放器和辅助坞分别设置合理最小尺寸。
- 关闭后主工作面回收全部空间，不留下兜底色块；任何停靠方向都不用实心竖线标活动态。

### 5.10 林埃悬浮入口与对话 `IFloatingChat`

- 入口悬浮于工作面，不占永久侧栏；使用中性纸 / 浅绿材质，状态通过小点表达。
- 打开后只出现独立消息承载、必要上下文标签和输入框；不追加覆盖整侧的兜底矩形。
- 用户消息使用浅 Palm 绿半透明气泡与深色文字，不使用大面积深绿；发送动作用居中的纸飞机图标。
- 后台任务不挂在聊天气泡下，而由独立 `TaskStrip` / 任务中心承载。
- 对话关闭后完整退场；全屏白板本身不被永久压缩。

## 6. 所有交互组件的状态矩阵

每个可操作组件至少定义：

| 状态 | 必须回答的问题 |
|---|---|
| Default | 它是什么，是否可操作 |
| Hover | 鼠标指向时可以做什么 |
| Focus | 键盘当前在哪里 |
| Pressed | 操作是否已被接收 |
| Selected | 它是否进入持续选择 |
| Loading | 是否禁止重复提交，原尺寸是否稳定 |
| Disabled | 为什么暂不可用，文字是否仍可读 |
| Empty | 用户下一步能做什么 |
| Error | 发生什么，能否重试或恢复 |
| Permission | 谁请求什么权限，允许多久 |

Hover、Focus、Selected 不能只做同一种浅绿色背景。状态首先通过边界、焦点环、图标或文字说明区分，颜色只是辅助。

这张状态矩阵是开发与验收清单，不是面向用户的产品内容，不应作为“基础页面最底部的一大块文字”出现在正式界面或视觉预览中。

## 7. 页面验证顺序

组件规范 v0.2 之后，不继续抽象造组件，按以下真实流程逐条验证：

1. 卡片库：采集链接 → 识别类型 → 筛选 → 打开 / 拖入白板。
2. 白板：创建节点 → 选择 / 拖动 → 分组 / 连线 → 全屏退场规则。
3. 视频研读：播放 → 字幕跳转 → 创建标注 → 回到卡片 / 白板。
4. 林埃悬浮对话：带当前工作面上下文发起请求 → 任务转交 → 结果回流。
5. 任务房间与记忆：多任务隔离 → 授权 → 产物 → 选择材料 → 压缩任务结晶。

每条流程只允许补充真正缺失的组件状态；若同一问题在两个页面反复出现，再提升为基础规范。

当前下一步正式进入第 1 条纵切，并把范围收紧为：桌面壳与可收起导航 → 卡片库真实预览 → 新建 / 进入白板 → 将现有卡片拖入画布 → 保存并在重启后恢复画布。首页最终编排、视频 provider、任务房间和复杂图表不阻塞这条纵切。

## 8. v0.2 冻结与待定

### 本轮可以冻结

- Palm 单一主配色，媒体功能不再引入蓝色；
- 紧凑、低圆角、高信息量的密度；
- 36 / 44 / 52 控件高度与间距阶梯；
- 横线文字 + 淡绿水墨活动态侧栏及其完全收起行为；

- coding 工具房间的产物分栏与执行者内嵌深度；
- 汇文明朝体与 Cascadia Code 的生产子集、包体积和多平台字体资产接入；
- 每个平台播放器的具体控件能力；
- 尚未跑通真实数据的空状态和统计口径。
