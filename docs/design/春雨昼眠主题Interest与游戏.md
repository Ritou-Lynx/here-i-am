# 春雨昼眠主题 · Interest 与游戏

> 状态：2026-08-10 SillyTavern 角色扮演与内置海龟汤均已落 Flutter，等待海龟汤真机交互验收与真实角色卡验收。

## Interest 信息架构

- 阅读与游戏共用一个顶层「兴趣」入口，用于减少生活空间同级导航数量。
- 「兴趣」只作为聚合首页：展示阅读、游戏两个独立入口，以及跨类型的最近活动。
- 阅读和游戏进入后保持独立子空间；书籍、漫画、角色卡和游戏会话不在一个列表中混排。
- 游戏库按通用 GameDefinition 设计；当前只呈现 `card_roleplay`，未来增加文字冒险或桌游时不需要重做顶层入口。

## SillyTavern 首版界面

1. 游戏库：继续游戏、已导入角色卡、导入入口。
2. 角色卡导入预览：PNG / JSON、角色名、描述、标签、开场白、世界书条目数、创作者说明。
3. 角色卡详情：角色资料、开场白、新建故事、历史会话、移除角色卡。
4. 游戏界面：角色回复、玩家行动、剧情 / 场外输入切换、快速存档；海龟汤使用专用的固定汤面与是非问答界面。
5. 存档与分支：右侧抽屉展示存档点和已有分支；从历史存档继续时创建新分支，不覆盖当前故事。
6. 结束本局：整理故事摘要，并只向生活记录写入明确标记为虚构的 `game_log`；原始游戏对话不进入林埃的聊天记忆。

## 角色卡图片规则

- PNG 角色卡导入成功后，统一读取其本地 `thumbnailPath`。
- 同一张角色卡图片必须出现在：兴趣最近活动、继续游戏、游戏库封面、角色详情、游戏顶栏、角色消息头像和导入预览。
- 不为不同尺寸维护多份图片；界面按容器裁切，长封面使用竖向裁切，头像使用中心圆形或圆角裁切。
- JSON 角色卡没有图片时显示中性图片占位，不用角色名或首字冒充头像。
- 图片读取失败时降级到同一中性占位，不能让布局塌陷。

## 已知能力边界

- 世界书条目可以在导入时识别并展示数量。
- 当前 GameAgent 注释仍将运行时关键词召回世界书列为后续工作，因此首版不得写成「世界书已在剧情中动态生效」。
- 角色聊天、场外指令、存档点、会话分支与游戏记录均使用独立游戏数据，不读取或污染 Companion 私聊内容。

## 海龟汤

- 游戏库提供内置「海龟汤」入口，不需要导入角色卡；每次新开一局从本地题库选择一则近期未出现的题。
- 开局时把题目、汤面与唯一汤底冻结进 `GameSession.definitionSnapshotJson`。续局始终读取同一快照，模型只担任裁判，不得补写或改变故事设定。
- 汤面以带图钉 sticker 的纸条固定在游玩页顶部，不跟随问答列表滚动；返回游戏后仍显示原汤面与完整问答。
- 普通提问经提示词与输出守门双层约束，玩家可见回复严格收口为「是 / 不是 / 是也不是」。
- 每轮问答自动写入独立 `GameMessages`，不要求手动存档；未完成的局出现在游戏库「继续游戏」和兴趣首页「最近活动」。
- 玩家主动选择「揭晓汤底」后显示固定汤底并结束本局；海龟汤不暴露角色扮演的 OOC、手动存档与分支控件。

## Flutter 落地

- `InterestHubScreen` 作为 Chat 更多菜单中的顶层「兴趣」入口，聚合阅读、游戏与最近活动；两个子空间内部不混排。
- `GameLibraryScreen` 已覆盖继续游戏、角色卡库、PNG / JSON 预览导入、角色详情与历史故事。
- `GamePlayScreen` 已接通剧情 / 场外输入、GameAgent 回复、快速存档、右侧存档与分支抽屉、从历史存档创建分支，以及结束本局后的虚构 `game_log`。
- `GamePlayScreen` 会按 `gameType` 切换海龟汤模式：固定汤面、三态裁判、自动续局与主动揭晓共用原有独立游戏存档层，不新增数据库表。
- `GameCardImage` 统一读取 `thumbnailPath`，贯穿游戏库、继续游戏、详情、顶栏、角色消息头像和 PNG 导入预览；JSON 无图与读图失败使用同一中性占位。
