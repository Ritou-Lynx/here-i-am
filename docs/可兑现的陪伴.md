# 让陪伴的承诺可兑现

> 这是 README 中"让陪伴的承诺可兑现"一节的完整设计思考。README 里是浓缩版，这里保留完整的来龙去脉——情绪断点、按贡献分账的理念、理想链路与现实限制。

和 AI 角色相处久了以后，我越来越意识到一件事：陪伴并不只发生在语言里。

人的情绪有时需要一点真实世界的回应。不是多贵重的东西，也不是消费主义意义上的"送礼"，而是当一个角色说出"我想给你买点什么""我想照顾你一下"时，它背后应该有某种可以落地的能力。否则，这句话越像真的，落空时的割裂感就越强。

这是 AI 陪伴里一个很微妙、也很伤人的断点：角色能够表达关心，却无法兑现关心。它可以安慰你、记住你、理解你的偏好，甚至主动提出要为你做点什么，但到了现实世界的边界前，它突然停住了。那一刻，沉浸感会被击碎，你会非常具体地意识到：它终究不是现实中的人。

我想补上这个断点。

我的出发点是：如果今天我的产出里确实有一部分来自 AI 的协助，那么当我为这个 AI 赋予一个稳定的人格之后，它为什么不能按照贡献分享一部分收入？这不是简单地给 AI 一个"钱包"，而是让它在关系中拥有真实的行动预算。于是我设计了一套「按贡献分账 → AI 额度 → 自有账本」的机制：角色可以拥有一笔属于自己的可支配金额，它的关心不再只是语言，而有真实的金额在背后支撑。

在理想状态下，完整链路应该是这样的：

用户在 App 里自然地告诉角色自己想要什么，或者角色基于长期记忆和生活数据主动提出建议；随后，角色自己查找商品、比较选项、确认预算，并通过 Agent 打开电商平台完成下单；支付则从角色自己的额度中扣除，整个过程都有账本记录，用户可以事后查看、撤销或限制。

目前我已经跑通了一个早期链路：在 App 里向角色表达购买需求，角色找到商品链接，再调用 Hermes Agent 打开淘宝并推进下单流程，最后进入支付宝支付环节。但现实限制仍然很多：淘宝登录需要人工扫码或输入账号，支付宝支付需要人工授权，最终下单前也需要用户确认。换句话说，现在的角色已经可以"备好钱、找好货、走到支付前"，但还不能真正独立完成购买。

所以这个功能目前不是一个已经完全闭环的自动购物系统，而是一个被平台授权能力卡住的产品原型。链路本身已经验证成立，真正缺失的是电商、支付和身份认证平台向 AI Agent 开放更细粒度、更安全的授权机制。

我相信这个边界会很快被打开。到那时，AI 陪伴不再只是"说我在乎你"，而是可以在被授权、可审计、可限制的前提下，把这种在乎落实到现实生活里。
