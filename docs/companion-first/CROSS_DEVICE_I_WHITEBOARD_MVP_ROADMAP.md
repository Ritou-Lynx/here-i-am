# 跨设备林埃核心与白板 MVP 路线图

> 状态：已确认，进入实施
> 日期：2026-08-13
> 当前权威分支：`v3-lab`

## 1. 目标

先让林埃从某一台设备中独立出来，再建设白板。

私人电脑作为第一版唯一权威核心节点；主力手机、备用手机和桌面白板是同一个林埃的不同入口。聊天、Memory V3、Dreaming、Record Organizer 与 Check-in 不在各端重复运行。客户端只缓存当前需要的数据，大型源文件按需获取。

MVP 最终需要证明这一晚能够成立：

1. 用户在主力手机分享截图并与林埃聊天。
2. 回家打开电脑，桌面端从同一条消息继续。
3. 用户在备课白板搜索并分屏打开小说，把具体情节与教学素材相连。
4. Check-in 唤醒林埃继续阅读，批注保存在林埃空间。
5. 林埃选择一条内容带入共同空间，说明自己的反应与推荐理由。
6. 全程没有重复消息、重复记忆、重复 Check-in 或设备间身份断裂。

## 2. 产品边界

### 2.1 聊天与白板

- 手机与桌面使用同一条聊天时间线，统一进入现有 Memory V3。
- 普通聊天默认不写 User-truth，继续遵守现有记忆契约。
- 聊天中的链接、截图和帖子不会因为聊过就自动成为白板素材。
- 只有用户或林埃明确选择“留下”时，片段或源内容才进入白板内容体系。

### 2.2 三个空间

空间区分的是主动修改权，不是读取权限：

- **用户空间**：用户完全自主；林埃可读取、建议，经一次性或长期授权后操作。
- **林埃空间**：林埃无需授权即可收藏、批注、连接、修正与删除；用户可见、可回应，但不能直接改写。
- **共同空间**：双方共同参与；林埃可在受限额度与范围内主动带入内容。

源内容归属、批注归属和显示位置相互独立。林埃阅读用户书库中的书时，原书仍属于用户；林埃的阅读进度、划线和批注属于林埃，通过锚点叠加显示在同一阅读器中。

### 2.3 白板组织

- 采用多白板、白板分组、嵌套白板和标签页等成熟组织模型。
- 同一源内容可作为引用出现在多张白板中，不复制原件。
- 全局资料库负责搜索原件；白板负责空间组织、关系表达与美观呈现。

## 3. 目标架构

```text
主力手机（轻量捕获） ─┐
备用手机（完整能力） ─┼─ Tailscale HTTPS ─→ 私人电脑：林埃核心
桌面白板（深度工作） ─┘                         ├─ 统一聊天
                                                  ├─ Memory V3 / Dreaming
                                                  ├─ Record Organizer
                                                  ├─ Check-in / 调度租约
                                                  ├─ 空间、授权与审计
                                                  ├─ 内容索引与关系
                                                  └─ 源文件对象存储
```

核心服务是唯一权威写入者。SQLite 与文件目录只由核心服务直接访问，客户端通过版本化 API 通信。未来迁移到私有服务器时，保持客户端协议与逻辑身份不变，只迁移权威数据和服务端配置。

## 4. 实施阶段

### Phase 0 — 同步身份地基（当前）

- [x] 确认私人电脑作为第一版 24 小时核心节点。
- [x] 为聊天消息增加全局稳定 ID 与来源设备 ID，保留本机整数 ID 兼容现有 UI 和 Dreaming。
- [x] 为既有消息生成兼容的稳定 ID，并建立唯一索引。
- [ ] 将 Dreaming、Memory Card sourceRef、共读证据与召回追踪逐步改为稳定消息引用。
- [x] 盘点 Memory V3 各表的权威数据、派生数据与可重建缓存，形成同步清单。

**退出标准**：新消息从写入开始就有跨设备身份；现有聊天、共读、召回定位和 Dreaming 回归不受影响。

### Phase 1 — 私人电脑核心最小服务

- [x] 固化版本化核心 API v0 契约与共享 JSON 模型：设备注册、消息提交、增量拉取、确认游标、健康状态。
- [x] 在私人电脑实现独立的核心 API v0 服务端与持久化 change feed，完成双设备、幂等、冲突回滚与重启恢复验证。
- [ ] 私人电脑导入一份现有数据库，成为唯一权威状态。
- [ ] 服务通过 Tailscale HTTPS 暴露，不允许远端直接访问 SQLite。
- [x] 每次提交使用幂等键；同一消息重复上传只写入一次。
- [ ] 建立设备租约：Memory V3、Dreaming、Record Organizer 和 Check-in 只在核心运行。
- [ ] 服务开机自启、崩溃恢复，并提供一致性快照与加密异地备份。

**退出标准**：两个测试客户端同时写入不会覆盖或重复；Check-in 和 Dreaming 各只执行一次。

### Phase 2 — 主力手机轻量入口

- [ ] 提供精简 flavor 或独立轻量壳，不打包阅读器、本地模型和重媒体能力。
- [ ] 支持聊天、近期缓存、通知、拍照、截图与系统分享。
- [ ] 分享默认进入聊天草稿；显式“收入白板”才创建长期素材。
- [ ] 离线写入本地 outbox，恢复连接后按幂等键补交。
- [ ] 明确显示核心在线、离线、待同步和失败状态。

**退出标准**：主力机分享截图后，备用机即时接续同一对话；双端短暂离线写入后可合并。

### Phase 3 — 桌面聊天与资料入口

- [ ] 桌面端接入同一聊天、Memory V3 和 Check-in 结果。
- [ ] 从聊天显式保存文本、图片、链接或附件到资料库。
- [ ] 建立源内容对象、归属、来源、哈希和按需下载机制。
- [ ] 支持全局搜索聊天、记忆与已导入资料。

**退出标准**：手机捕获的内容可在桌面继续处理，聊天与记忆没有表面断裂。

### Phase 4 — 白板差异化纵切面

- [ ] 多白板、分组、嵌套白板与标签页导航。
- [ ] 用户空间、林埃空间、共同空间及操作审计。
- [ ] 导入 TXT / EPUB，全文搜索、分屏阅读、稳定文字锚点、划线与批注。
- [ ] 用户与林埃的批注分属各自，但可在同一阅读器叠加显示。
- [ ] Check-in 可继续一次未完成阅读；大多数内容不沉淀。
- [ ] 林埃可把少量片段从自己的空间带入共同空间，并保留来源、反应和推荐理由。

**退出标准**：完成“导入书籍 → 林埃自主阅读 → 林埃空间沉淀 → 共同空间分享”的真实闭环。

### Phase 5 — 媒介与白板能力扩展

按统一的“源内容—稳定锚点—归属批注—跨空间引用”模型扩展：

1. PDF 文本锚点与页面区域；
2. 图片区域；
3. 视频 / 动漫时间段、字幕与画面；
4. 网页文章和社交媒体片段；
5. 手写笔迹与 OCR 识别层；
6. Word 深度兼容、复杂连线、布局和大画布性能。

## 5. 同步原则

- 权威数据与大文件不要求每台设备全量持有。
- 消息和操作使用全局唯一 ID；本机整数 ID只作兼容索引，不跨设备引用。
- 删除、修正、反馈和权限变化都以操作形式同步并可审计。
- 派生数据必须标明生成版本与来源，可由权威源重建。
- 客户端增量拉取使用不透明游标，不能只依赖设备时钟。
- 现有 `.memexdata` 继续承担迁移、备份和灾难恢复，不承担日常多端合并。
- 核心离线时客户端允许捕获与排队；需要推理的回复等待核心恢复。

## 6. 暂不做

- 不先复刻 FlexNote 全部功能。
- 不让多台设备各自运行一套 Memory V3 或 Check-in 再尝试合并结果。
- 不用高频上传整包数据库伪装实时同步。
- 不把浏览过的全部网页、帖子和视频自动收入白板。
- 不在第一版解决多人协作或公共云账号体系。
