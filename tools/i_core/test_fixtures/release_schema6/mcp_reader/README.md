# Synthetic legacy MCP reader fixture

This directory contains exactly six byte-preserved production modules from the authorized legacy reader version. The server entry SHA-256 is `adfc88126c6d7ee047fd7fed7eda6b3b536c9e1fe0baffafbedc290b6c5554d6`. `source-inventory.json` pins every module. `.gitattributes` disables line-ending conversion for the legacy subtree so Windows and CI verify identical bytes. No state, configuration, credentials, logs, database or Git history was copied.

The static closure is server -> oauth, diagnostics, mcp, writeback; mcp -> writeback. The server also dynamically imports the included i_memory reader at its original relative location. All other imports are Node built-ins. The optional identity JSON is supplied by a fresh synthetic `I_HOME`; default production identity/state paths are never needed.

## API

- `verifyLegacySourceInventory()` checks all six file hashes and byte lengths. `LEGACY_SOURCE_ROOT`, `LEGACY_ENTRY_PATH`, and `LEGACY_ENTRY_SHA256` expose the pinned inventory location.
- `createSyntheticReaderState({ syntheticRoot, coreDbPath, primaryCharacterId = 'lin-ai', query = 'synthetic', protectDirectory })` creates a fresh child directory containing synthetic memory SQLite, policy, OAuth state, identity, and diagnostic directory. The optional synchronous `protectDirectory(path)` callback runs on readerRoot and each state/identity/log directory while empty, before any state write. The caller must explicitly supply a fresh synthetic root; the candidate Core path must be within it. The helper never opens or manages Core.
- `legacyReaderEnvironment(state)` supplies explicit paths, disables writeback, and permits the synthetic OAuth callback. The launcher's environment must drop inherited `I_*`, `NODE_OPTIONS`, and `NODE_PATH` before applying these values. No test loader or `NODE_OPTIONS` patch is used here.
- `legacyReaderCliArgs({ state, port, coreUrl })` invokes the original `server.mjs serve`. All DB/state/diagnostic paths and all network endpoints are explicit. `coreUrl` is unused with writeback disabled and defaults to loopback port 1; callers can provide their synthetic Core endpoint.
- `allocateSyntheticLoopbackPort()` allocates a random loopback port; like other reserve-and-release test helpers it has a small allocation/bind race, which fails visibly rather than selecting an existing service.
- `connectLegacyMcpReader({ state, base, requireMessage = true })` connects to an already-started synthetic legacy CLI: actual HTTP OAuth registration, passphrase/PKCE authorization, token exchange, MCP initialize, initialized notification, and real `i_recall`. It asserts successful real reads and nonempty synthetic memory/Core message responses by default. Seed a Core message with the state query and primary character first. `requireMessage:false` is only for explicit empty-Core cases; the real SQL query still executes.
- `startLegacyMcpReader({ state, nodePath, coreUrl, requireMessage })` uses the same connection flow and owns only its new legacy MCP child. It returns `child`, `cliArgs`, `base`, `token`, `sessionId`, `firstRecall`, `recall(query)`, `close()`, and synthetic diagnostics. Tokens/passphrases are ephemeral test inputs and must not be logged or added to evidence artifacts.
- `syntheticHttpRequest` and `mcpPost` are shared HTTP helpers restricted to explicit loopback bases. OAuth redirect responses are parsed, never followed or sent off-machine.

Run `node --test tools/i_core/test_fixtures/release_schema6/mcp_reader/helper.test.mjs` with a Node version supporting `node:sqlite`. This verifies source hashes and a complete real legacy CLI read against newly synthesized data; it is not a production deployment or device acceptance test. Integration lifecycle tests should additionally assert Core ownership/schema transitions themselves. External timeout instrumentation, if needed, belongs to the integration harness and must preserve the pinned entry bytes.

## Exact committed candidate smoke

`node smoke_candidate.mjs <protected-release-directory> <external-manifest-sha256> --synthetic-mcp-only` verifies the exact independently assembled committed release, then runs only freshly synthesized state, keys, custody, OAuth, policy, memory and legacy source. It requires Windows and the pinned Node. It asserts an actual MCP message read, the maximum 3-second stop grace, clean Core close, owned Jobs empty, exclusive database reopen, and a second login with a new MCP process and the same synthetic message. It never loads production configuration or registers tasks. Temporary lab cleanup occurs only after every owned process exited; the supplied candidate itself is retained unchanged.
