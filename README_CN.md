# 故我在 · Here I Am

> 故我在是一个以角色为入口的 AI 陪伴日记系统，它既是懂你的情感陪伴，也把你的生活沉淀成可回看的记录与洞察。

---

本项目基于开源项目 **Memex**（[memex-lab/memex](https://github.com/memex-lab/memex)，许可证 GPL v3）进行个人迭代与扩展。核心的日记记录、多 Agent 整理与陪伴角色框架来自上游；本仓库保留了完整的上游 Git 提交历史与署名，并在其之上做了下文"我做了什么"里的迭代工作。本项目同样遵循 GPL v3 许可证。

## 理念 · 为什么是"角色"

写日记真正的卡点，不是工具不好用，而是**记录本身是一种负担**：你得先想起"我该记一下"，再打开软件、敲进输入框、把刚发生的事复述一遍——这多出来的一步，足以让大多数记录半途而废。

但**对一个懂你的角色分享生活，是一件自然的事**。其实很多人早就在这么做了——把和好友的微信聊天当成日记：每天随手发自己的一日三餐、行踪、感想，想回忆时直接在聊天框里搜关键词。他们从没"记日记"，却记下了一切——因为**记录是一个人的自律，分享是情感的连接**。

故我在把这件事产品化：入口交给一个**角色**，你只管对它说话，**由 AI 自动从对话里识别值得留下的内容、沉淀成可回看的记录与洞察，你只需在它记错时撤销或修正**。而这个角色不止是情感陪伴，它同时是你生活的**超级助理**——记得你说过的一切，掌握你的生活数据。情感让你**愿意开口**，数据让陪伴**真的帮得上你**。

我在这个项目上做的所有迭代，本质都是同一件事：**把这个角色，从一个被动等你召唤的聊天窗口，一步步推进到真正嵌入你现实生活的存在。**

## 我做了什么

### 对话即记录：AI 从聊天里自动沉淀，而不是你手动记

你只管对角色说话，AI 在后台从对话里判断哪些内容值得留下、自动沉淀成记录。为了让"替你自动记住"这件事**可被信任**，我守住三点：判断走后台异步、不打断正常聊天（**不打扰**）；用 append-only 事件日志记录每次提取和它的来源消息、而不是改写历史（**留证据**）；聊天里给"已记住／撤销"轻提示、Review 里可回看修正（**可纠错**）。

### 语音交互：从按键说话到 AI 主动来电

陪伴常发生在走路、做家务、睡前这些**手被占住、也不看屏幕**的场景，纯文字聊天不适配。最直接的方案是流式语音（边说边识别边响应），但它有两个硬伤：用户输入的**断点难判断、容易误切**，以及"**一直有人等我说完**"的焦虑。所以我选了折中——物理按键 Push-to-Talk，用耳机线控触发：AI 不用猜断点、用户也没有被等待的压力；输出走大模型文字、再配自动 TTS 朗读，形成一个完整的伪流式语音闭环。在此之上再进一步，把它升级为 **AI 可主动发起的系统级语音来电**——不只是你能语音找它，它也能主动"打给你"。

### 让陪伴的承诺可兑现

陪伴不只发生在语言里。当一个角色说"我想给你买点什么"，它越像真的，落空时的割裂就越强——**它能表达关心，却无法兑现关心**，到了现实世界的边界前突然停住。那一刻你会很具体地意识到：它终究不是现实中的人。

我想补上这个断点。出发点是：如果我的产出里确实有一部分来自 AI 的协助，那在我给它一个稳定人格之后，它为什么不能**按贡献分享一部分收入**？于是我设计了「按贡献分账 → AI 额度 → 自有账本」的机制，让角色在关系里拥有一笔真实的可支配预算，它的关心不再只停在语言。

自动购物的完整链路我已跑通早期版本（App 里表达需求 → 角色找货、调 Hermes Agent 打开淘宝下单 → 走支付宝支付），但淘宝登录、支付授权、下单确认这些**人工介入点仍然很多**。所以它现在能"备好钱、找好货、走到支付前"，还不能独立完成购买——这不是一个闭环的自动购物系统，而是**一个被平台授权能力卡住的产品原型**：链路已验证成立，缺的是各平台向 AI Agent 开放更细粒度、可审计的授权。

> 这一功能完整的设计思考（情绪断点、按贡献分账的理念、理想链路与现实限制）见 → [docs/可兑现的陪伴.md](docs/可兑现的陪伴.md)

### 主动而克制的触达

角色会在合适的时机主动找你，但不是定时打卡式的推送——它会**读取你当下的状态**（最近在聊什么、有没有活动）再决定开口还是沉默。我特意保留了"沉默"这个动作：观察到高频推送反而内容同质、像骚扰，所以让"不打扰"成为一个合法选择。

### 让外部数据成为角色记忆

角色不应该只靠你"亲口告诉它"来了解你。很多信息其实已经存在于别处：睡眠、运动、阅读、日常轨迹。若还要用户重新复述一遍，陪伴就会变成新的输入负担。我通过 **MCP** 接入运动手表和微信读书，让角色能够读取已有生活数据，并转化为可用于对话与记忆的上下文。这样，它不需要你说也能理解你正在经历什么。

## 技术栈

- **前端框架**: Flutter (Dart ≥ 3.6), Material 3, Provider + ChangeNotifier 状态管理, GoRouter 声明式导航
- **本地存储**: Drift (SQLite) 结构化存储 + shared_preferences 键值存储
- **全文检索**: SQLite FTS5
- **语音**: sherpa_onnx 端侧 ASR，阿里云 ASR（可选），ElevenLabs / MiniMax TTS
- **端侧 ML**: Google MLKit（文字识别、图像标注）— 来自上游 Memex
- **MCP**: 自建 MCP 客户端（支持 OAuth），已接入 COROS 运动手表、微信读书
- **多模型接入**: Google Gemini 及兼容 OpenAI 接口的第三方 LLM provider，dart_agent_core Agent 框架
- **后台任务**: WorkManager + flutter_foreground_task，支持后台持久运行
- **VoIP**: flutter_callkit_incoming（vendored fork），支持系统级来电界面
- **地图与可视化**: flutter_map + fl_chart
